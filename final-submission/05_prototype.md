## 1. 이게 뭔가

**목업이 아니라 실제로 작동하는 프로토타입이다.**

- 추천 엔진(**하드필터 → 무드 유사도 → MMR 다양성 → 안전빵 → 이유 템플릿**)이 HTML 안의 JavaScript로 **실제 구현돼 있다.**
- 코디 사진 **39장은 실사진**이며, 사람이 직접 무드·색·TPO·온도밴드·비 적합성으로 태깅했다.
- 날씨를 바꾸면 **추천 결과가 실제로 달라진다.** 화면 전환만 하는 클릭더미가 아니다.

```
      ↓
  ┌─ 온보딩 (스크리닝) ────────────────────┐

  │    → (남성·타깃 밖: 정직한 "준비 중" 안내)   *2026-07-15: 별도 나이 화면 통합*
  └────────────────────────────────────────┘
      ↓
  ┌─ 취향 퀴즈 3문항 ──────────────────────┐
  │  Q1 "어떤 게 제일 나 같아요?"     무드
  │  Q2 "손이 자주 가는 색은?"        색
  │  Q3 "요즘 옷 입고 가는 곳은?"     TPO
  │    *2026-07-15: 고른 항목에 선택 표시 + [다음] 버튼*
  └────────────────────────────────────────┘
      ↓
  참고 사진 선택  ← "사진 없이 취향으로 볼래요" 경로 항상 존재
      ↓
  동네 검색 → 날씨 선택 (데모)  ← 사진 → 동네 → 날씨 순 · 실서비스는 GPS + 기상청 API 자동
      ↓
  ┌─ 오늘의 3코디 (코어 화면) ─────────────┐
  │  "비 오는 오늘, 입을 만한 3가지"
  │  결정 전 = 사진 + 이름 + 한 줄 이유   ← 읽을 게 많으면 결정이 느려진다
  │  결정 후 = 「옷장에서 꺼낼 것」 체크리스트로 변신 + 나머지 2장 흐려짐
  │  [🔄 다른 거 보여줘] (하루 1회) · [📷 이 사진처럼 골라줘]
  └────────────────────────────────────────┘
      ↓ "오늘 이거 입을래" 탭 1번 = 결정 (하루 한 벌)
  ┌─ 하단 3탭 ─────────────────────────────┐
  │  오늘 (코어)  ·  날씨  ·  기록(코디 캘린더)
  │  날씨: 온도 + 강수확률·강수량·습도·일교차 2×2 지표 + 시간별 막대
  │  기록: 날짜 클릭 → 그날 상세 전체화면 (코디 사진 업로드 + 착용 배지)
  └────────────────────────────────────────┘
```

**폴백 화면도 구현돼 있다** — "오늘은 딱 맞는 코디가 조금 부족해요" (= PRD FR-14 "결과 없음을 보여주지 않는다"의 실물).

## 4. 걸어보기 시뮬레이션 — 서연, 화요일 아침

> **이 제품이 실제 사람 앞에서 어디서 막히나**를 직접 걸어본 기록이다(상세 = [08_user_flow §5](../submission/08_user_flow.md)).
> 규칙: **좋게 봐주지 않는다.** 서연은 앱을 도와주려고 쓰는 사람이 아니다.
> **배경** — 월요일 밤 11:20, 침대에서 친구 링크로 첫 설치. 화요일 아침 8:10, 비, 9시 수업, **옷 결정에 쓸 시간 3~5분.**

### 막힘 8개 — 무엇이 막혔나 → 어떻게 됐나

| # | 무엇이 막혔나 | 지금 어떻게 됐나 | 상태 |
|---|---|---|---|
| ① | 밤 11시에 **위치 권한 팝업** — "밤에 위치를 왜?" 이탈 위험 | 프로토타입은 **동네 검색식(데모)**이라 팝업 자체가 없음. 실서비스 GPS 요청 타이밍은 별개 과제 | ⚪ 미확인 |
| ② | **첫 진입은 아침이 아니다** — 밤 11시에 "오늘 코디"는 이미 끝난 날 | **밤 모드(17시~새벽 4시)**: 대상일이 내일로 바뀌고 *"지금은 밤이에요 — 내일 아침 코디를 골라뒀어요"* 배너 (B8) | ✅ 고침 |
| ③ | **D1에 돌아올 장치가 없다** — 내일 아침 이 앱을 기억할 이유가 없음 | 첫 세션 끝에 **[내일 아침, 여기서 봐요 — 홈화면에 추가]** 화면(위젯·알림 미리보기, *"실물 아님"* 표기) | ✅ 고침 |
| ④ | 아침에 **[어제 이거 입었어요?]** 배너 — "어제 처음 깔았는데?" | 어젯밤 저장을 안 했으니 배너가 **안 뜬다.** 버그가 아니라 정상 동작 | ✅ 정상 |
| ⑤ | **옷장 앞의 벽** — 결정은 끝났는데 "사진 속 흰 블라우스가 내 옷장에 없다"(리스크 #3) | **시점으로 갈랐다**: 결정 전=사진만, **결정 후**=고른 카드에 [옷장에서 꺼낼 것] 체크리스트. + 「입었어요」가 이 손실을 재는 **유일한 온도계** | ✅ 고침 |
| ⑥ | **3장 다 별로 + 리롤도 씀** → "오늘은 여기까지예요" → 어제 옷으로 회귀 | 탈출구 1개(원칙 1)의 대가는 감수하되 *"오늘 날씨에 맞는 게 이만큼이라서요"* 이유를 준다(부실이 아니라 판단) | ⚪ 미확인 |
| ⑦ | **온보딩 되돌아가면 이전 답이 안 보인다** — 다시 처음부터 고민 | 원래 "남음"이었으나 **2026-07-15 퀴즈에 선택 표시 + [다음] 버튼이 들어가 사실상 해소** | 🟢 사실상 해소 |
| ⑧ | **주말 건너뛰면 "어제 배너"가 영영 안 뜬다** | "어제"가 아니라 **마지막 미응답 기록**을 묻는다. 금요일에 정하고 월요일에 열어도 신호가 안 샌다 | ✅ 고침 |

> **집계:** 2026-07-13에 6개 우선순위를 뽑아 **5개를 반영**했고, 마지막 1개(⑦ 선택 표시)는 2026-07-15 퀴즈 개편으로 **사실상 닫혔다.** ①·⑥은 이유 문구는 들어갔으나 **아직 눈으로 확인하지 않은 상태**다.

### ⑤가 왜 "4번째 답"이 됐나

문서는 *"아이템 텍스트를 카드에서 크게"* 를 1안으로 뒀는데, 만들어보니 **고르는 순간엔 그게 방해였다.** 읽을 게 많을수록 결정이 느려진다.
→ 그래서 **시점으로 갈랐다.** 8:10:18에 필요한 건 사진이고, 8:10:20 **옷장 앞에서** 필요한 건 목록이다. 같은 화면이 시점에 따라 다른 걸 준다.

### 한 줄 요약

> **결정은 대신 해줬다. 그런데 실행은 여전히 혼자다.**
> 아침 8:10~8:10:18의 18초(결정)는 우리가 이겼고, **8:10:20의 옷장 앞(실행)은 아직 안 이겼다.**
> 그 20초 뒤가 리스크 #3이고, **「입었어요」가 그걸 재는 유일한 온도계**다.

## 5. 자리표시 — 실서비스에서 교체될 부분 (정직하게)

> 아래는 **프로토타입의 한계이자, 실서비스에서 교체가 이미 설계된 지점**이다.
> 🚫 **이 목록에 없는 새 껍데기를 만들지 않는다** (AGENTS.md §9-1).

| 지금 (프로토타입) | 실서비스 | 왜 지금은 이렇게 |
|---|---|---|
| **날씨 = 데모 4시나리오를 직접 선택** | **기상청 API가 자동으로** 오늘 체감온도·강수를 읽음 | 프로토타입에서 여러 날씨를 즉시 비교해 보기 위해 |
| **동네 = 검색해서 직접 선택** *(2026-07-15)* | **GPS가 자동으로** 잡음 (거부 시에만 수동 선택 = J1) | 날씨와 같은 이유. 화면에도 *"진짜 앱은 GPS로 동네를, 기상청에서 날씨를 자동으로 읽어와요"* 라고 밝힌다 |
| **유사도 = 진짜 CLIP 임베딩** ✅ *(웹 주소로 열었을 때)* | **같은 방식 + pgvector**(서버에서 미리 계산) | 브라우저가 매번 39장을 임베딩하는 건 데모라서 가능한 것 |
| **저장 = 브라우저 메모리**(localStorage) | **Supabase DB (본인만 접근)** | 서버 없이 단일 파일로 돌리기 위해 |
| **콘텐츠 검수 = 🧪 시뮬레이터의 UI 껍데기** | **업로드 시 자동 모더레이션**(FR-5) | 차단됐을 때 화면만 확인하려는 것 — 실제 검수는 아직 없음 |
| **지표 = 📊 패널 (브라우저에 쌓임)** *(2026-07-14)* | **GA4 / Amplitude / Supabase** 로 전송 · **유저 단위** 집계 | `track()` 함수 **속만** 갈아끼우면 된다 — 부르는 8곳은 그대로. 패널에도 *"이 브라우저에서 일어난 일만 셉니다"* 라고 밝힌다 |

### 📊 지표 패널 — PRD §4 "측정할 수 있어야 한다"의 실물 (2026-07-14 추가)

우하단 **📊 지표** 버튼. 계측 이벤트 **8종**(`앱_열기` `퀴즈_완료` `참고사진` `3장_표시` `결정` `결정_변경/취소` `리롤` `착용_답변`)을 심고, 이걸로 아래를 실제로 계산해 보여준다.

- **북극성 — D1 아침 재방문** (마지막 방문일과 오늘을 비교)
- **퍼널** — 앱 열기 → 퀴즈 완료 → 3장 표시 → 결정
- **품질** — 결정률 · **"입었어요" 회수율** · 리롤률

> ⚠️ **결정률이 거짓말하지 않게 한 두 가지:** ①화면은 저장·착용답변 때마다 다시 그려지므로 **같은 3장은 한 번만** 노출로 센다(안 그러면 분모가 부풀어 결정률이 낮게 나온다). ②**"갈아타기"는 새 결정으로 세지 않는다**(안 그러면 결정률이 100%를 넘는다).

**중요:** 자리표시는 **엔진의 구조가 아니라 데이터 소스**다. 하드필터 → 유사도 → MMR → 안전빵 → 이유의 **순서와 로직 자체는 실서비스와 동일하다.**

### ⚠️ 참고사진 매칭은 "진짜"다 (2026-07-13 추가)

참고 사진 업로드가 **실제로 추천을 바꾼다.** 껍데기가 아니다.

- **CLIP(`Xenova/clip-vit-base-patch32`)이 브라우저 안에서 직접 돈다.** 서버·API 키·비용 0원 (transformers.js).
- 올린 사진 → **512차원 분위기 좌표** → 라이브러리 39장과 **코사인 유사도** → 가까운 순으로 랭킹.
- **검증됨:** 같은 취향·같은 날씨에서 러블리 무드 사진을 올리면 추천 3장이 실제로 러블리·시크 쪽으로 바뀐다.

**단, `file://` 더블클릭에서는 브라우저 보안(CORS) 때문에 모델을 못 불러온다.**
→ 이때는 **자동으로 태그 기반 추천으로 폴백**하고, 화면에 *"오프라인 데모 모드"* 라고 **정직하게 표시**한다.
→ **AI 매칭을 보려면 반드시 웹 주소(Netlify 등)로 열 것.** (§6)

## 6. MVP 링크 제출 방법

프로토타입은 **단일 HTML + 이미지 폴더**라 빌드가 필요 없다. 그대로 정적 호스팅에 올리면 링크가 된다.

**가장 빠른 방법 (선택):**
- **Netlify Drop** — [app.netlify.com/drop](https://app.netlify.com/drop) 에 `prototype/` 폴더를 **드래그&드롭**. 계정 없이 즉시 URL 생성. *(가장 쉬움)*
- **GitHub Pages** — 레포에 올리고 Settings → Pages 활성화. 무료·영구.
- **Vercel** — 폴더 드래그 배포. 나중에 실제 앱과 같은 스택.

> ⚠️ **제출 시 반드시 함께 적을 것:** "날씨는 데모 4시나리오 선택식이며, 실서비스는 기상청 API 자동 연동" — 안 적으면 심사자가 날씨 자동화가 안 된 것을 **결함**으로 읽는다. 적으면 **의도된 데모 설계**로 읽힌다.

**모바일에서 보기:** 프로토타입은 모바일 화면 비율(`#phone` 프레임)로 설계돼 있다. 데스크톱에서도 폰 프레임 안에 렌더된다.
