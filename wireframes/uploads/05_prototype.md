# rainism — 디자인 프로토타입 & MVP

> 작성 2026-07-13 · 파일: [`prototype/rainism_prototype_v1.html`](../prototype/rainism_prototype_v1.html)
> **실행: 더블클릭.** 설치·서버·터미널 불필요. 단일 HTML + 실사진 39장.

---

## 1. 이게 뭔가

**목업이 아니라 실제로 작동하는 프로토타입이다.**

- 추천 엔진(**하드필터 → 무드 유사도 → MMR 다양성 → 안전빵 → 이유 템플릿**)이 HTML 안의 JavaScript로 **실제 구현돼 있다.**
- 코디 사진 **39장은 실사진**이며, 사람이 직접 무드·색·TPO·온도밴드·비 적합성으로 태깅했다.
- 날씨를 바꾸면 **추천 결과가 실제로 달라진다.** 화면 전환만 하는 클릭더미가 아니다.

## 4. 자리표시 — 실서비스에서 교체될 부분 (정직하게)

> 아래는 **프로토타입의 한계이자, 실서비스에서 교체가 이미 설계된 지점**이다.
> 🚫 **이 목록에 없는 새 껍데기를 만들지 않는다** (AGENTS.md §9-1).

| 지금 (프로토타입) | 실서비스 | 왜 지금은 이렇게 |
|---|---|---|
| **날씨 = 데모 4시나리오를 직접 선택** | **기상청 API가 자동으로** 오늘 체감온도·강수를 읽음 | 프로토타입에서 여러 날씨를 즉시 비교해 보기 위해 |
| **동네 = 5개 중 직접 선택** *(2026-07-14)* | **GPS가 자동으로** 잡음 (거부 시에만 수동 선택 = J1) | 날씨와 같은 이유. 화면에도 *"진짜 앱은 GPS로 동네를, 기상청에서 날씨를 자동으로 읽어와요"* 라고 밝힌다 |
| **유사도 = 진짜 CLIP 임베딩** ✅ *(웹 주소로 열었을 때)* | **같은 방식 + pgvector**(서버에서 미리 계산) | 브라우저가 매번 39장을 임베딩하는 건 데모라서 가능한 것 |
| **저장 = 브라우저 메모리**(localStorage) | **Supabase DB (본인만 접근)** | 서버 없이 단일 파일로 돌리기 위해 |
| **지표 = 📊 패널 (브라우저에 쌓임)** *(2026-07-14)* | **GA4 / Amplitude / Supabase** 로 전송 · **유저 단위** 집계 | `track()` 함수 **속만** 갈아끼우면 된다 — 부르는 8곳은 그대로. 패널에도 *"이 브라우저에서 일어난 일만 셉니다"* 라고 밝힌다 |

### 📊 지표 패널 — PRD §4 "측정할 수 있어야 한다"의 실물 (2026-07-14 추가)

우하단 **📊 지표** 버튼. 계측 이벤트 **8종**(`앱_열기` `퀴즈_완료` `참고사진` `3장_표시` `결정` `결정_변경/취소` `리롤` `착용_답변`)을 심고, 이걸로 아래를 실제로 계산해 보여준다.

- **북극성 — D1 아침 재방문** (마지막 방문일과 오늘을 비교)
- **퍼널** — 앱 열기 → 퀴즈 완료 → 3장 표시 → 결정
- **품질** — 저장률 · **"입었어요" 회수율** · 리롤률

> ⚠️ **저장률이 거짓말하지 않게 한 두 가지:** ①화면은 저장·착용답변 때마다 다시 그려지므로 **같은 3장은 한 번만** 노출로 센다(안 그러면 분모가 부풀어 저장률이 낮게 나온다). ②**"갈아타기"는 새 결정으로 세지 않는다**(안 그러면 저장률이 100%를 넘는다).

**중요:** 자리표시는 **엔진의 구조가 아니라 데이터 소스**다. 하드필터 → 유사도 → MMR → 안전빵 → 이유의 **순서와 로직 자체는 실서비스와 동일하다.**

### ⚠️ 참고사진 매칭은 "진짜"다 (2026-07-13 추가)

참고 사진 업로드가 **실제로 추천을 바꾼다.** 껍데기가 아니다.

- **CLIP(`Xenova/clip-vit-base-patch32`)이 브라우저 안에서 직접 돈다.** 서버·API 키·비용 0원 (transformers.js).
- 올린 사진 → **512차원 분위기 좌표** → 라이브러리 39장과 **코사인 유사도** → 가까운 순으로 랭킹.
- **검증됨:** 같은 취향·같은 날씨에서 러블리 무드 사진을 올리면 추천 3장이 실제로 러블리·시크 쪽으로 바뀐다.

**단, `file://` 더블클릭에서는 브라우저 보안(CORS) 때문에 모델을 못 불러온다.**
→ 이때는 **자동으로 태그 기반 추천으로 폴백**하고, 화면에 *"오프라인 데모 모드"* 라고 **정직하게 표시**한다.
→ **AI 매칭을 보려면 반드시 웹 주소(Netlify 등)로 열 것.** (§5)

## 5. MVP 링크 제출 방법

프로토타입은 **단일 HTML + 이미지 폴더**라 빌드가 필요 없다. 그대로 정적 호스팅에 올리면 링크가 된다.

**가장 빠른 방법 (선택):**
- **Netlify Drop** — [app.netlify.com/drop](https://app.netlify.com/drop) 에 `prototype/` 폴더를 **드래그&드롭**. 계정 없이 즉시 URL 생성. *(가장 쉬움)*
- **GitHub Pages** — 레포에 올리고 Settings → Pages 활성화. 무료·영구.
- **Vercel** — 폴더 드래그 배포. 나중에 실제 앱과 같은 스택.

> ⚠️ **제출 시 반드시 함께 적을 것:** "날씨는 데모 4시나리오 선택식이며, 실서비스는 기상청 API 자동 연동" — 안 적으면 심사자가 날씨 자동화가 안 된 것을 **결함**으로 읽는다. 적으면 **의도된 데모 설계**로 읽힌다.

**모바일에서 보기:** 프로토타입은 모바일 화면 비율(`#phone` 프레임)로 설계돼 있다. 데스크톱에서도 폰 프레임 안에 렌더된다.
