# rainism MVP 구현 계획 v1

> **작성 2026-07-10** · 기준 = [`rainism_PRD_MVP_v1.md`](rainism_PRD_MVP_v1.md) · 정본 앵커 = [`CLAUDE.md`](../CLAUDE.md)
> 이 문서는 **"어떤 순서로 만들고, 무엇이 완성되면 다음으로 넘어가는가"** 만 규정한다. 코드·DDL·API 형식은 규정하지 않는다(그건 PRD와 동일하게 구현자가 정한다).

## 이 계획을 읽는 법 — 게이트 방식

각 단계는 **완료 게이트**를 통과해야 다음으로 넘어간다. 게이트 = "이게 관찰되면 이 단계는 끝난 것"이라는, 눈으로 확인 가능한 조건. 게이트를 안 통과했는데 다음으로 가면 나중에 재작업이 커진다(특히 스파이크 게이트).

- 🔴 **게이트** = 통과 못 하면 다음 단계 착수 금지
- 🔬 = PRD §16 미결정. 해당 단계 착수 전 반드시 확정(임의 고정 금지)
- 🚫 = PRD §17. 되살리기 금지

## 큰 그림 — 두 트랙 + 임계경로

이 제품은 **두 개의 긴 축**이 동시에 굴러야 검증에 도달한다.

```
트랙 A (앱/엔지니어링) ─────────────────────────────────────────►
  Phase 0 확정게이트 → Phase 1 골격(스파이크 무관) → Phase 2 추천엔진 → Phase 3 하드닝 → Phase 4 검증출시
                                    ▲                    ▲                              ▲
                                    │ 스파이크① 결과      │ 시드 라이브러리              │ 완성 라이브러리
트랙 B (라이브러리/콘텐츠) ──────────┴────────────────────┴──────────────────────────────┘
  커버리지 매트릭스 → 소싱(예산 최소) → 시드 50~100장 → 목표 규모(~700 or 매트릭스 최소)
```

- **임계경로(가장 오래 걸리는 길) 2개:** ①스파이크①(표현 방식 확정) ②라이브러리 소싱. **둘 다 Phase 0부터 즉시 시작**한다. 이 둘이 안 끝나면 추천 엔진(제품의 심장)을 못 켠다.
- **핵심 전략:** 스파이크·소싱이 도는 동안 **손 놓지 않는다.** 추천 엔진을 뺀 앱 전체(온보딩·날씨·업로드·저장·계측)는 스파이크 결과와 **무관하게** 먼저 완성한다(Phase 1). 그래서 "병행"으로 결정한 것.
- **두-갈래 아키텍처 유지(PRD AP-1):** 무거운 로직(추천·날씨)은 서버 경유, 저장·조회는 데이터 계층 직접.
- **AI 격리(PRD AP-2):** 비싼 AI(태깅·임베딩)는 유저가 오기 전 오프라인 배치에서만. 실시간 아침 경로엔 AI 호출 없음.

## Phase 0 — 확정 게이트 (빌드 전 / 스파이크 + 미결정 정리)

**목표:** 나중에 뒤집히면 재작업이 큰 3가지를 닫고, 지금 정할 수 있는 정책을 못 박는다. 코드는 거의 없다(샘플·스프레드시트·노트북 수준).

**할 일**

| # | 작업 | 산출 |
|---|---|---|
| S0-1 | **스파이크① 표현 바이크오프** (PRD §14-1, 가장 중요) — 라이선스/샘플 사진 100~200장 + 무드 라벨로 후보 표현 방식(임베딩 모델들 / 메타태그+임베딩 하이브리드)을 **사람이 top-3 관련성**으로 비교 | 표현 방식 1개 확정 + **취향 프로필 산출법** 확정(🔬 §16-1,2) |
| S0-2 | **스파이크② 커버리지 매트릭스** (PRD §14-2) — `무드×TPO×체감온도밴드×강수` 셀별 최소 장수 | 총 목표 규모·우선 셀 숫자(🔬 §16-10) |
| S0-3 | **스파이크③ 규제 체크** (PRD §14-3) — PIPA 동의·보관, 2026.7 모더레이션 최소 요건, GPS 회피 위해 동(洞) 단위 | 동의 문구·보관기간·모더레이션 방식(🔬 §16-6) |
| S0-4 | **미결정 정책 확정** — 아래 "결정 필요" 표 참조 | 정책값 고정 |

**S0-4에서 닫아야 할 정책** (일부는 이전 세션에서 이미 결정 — *확인만*)

| 카피 톤 | ✅ 확정 | 다정한 친구(부드러운 존댓말) |

| 참고사진 보관 | 🔬 권장 | 표현만 남기고 원본 24h 내 삭제 |
| 재방문 트리거 | 🔬 권장 | 홈화면 추가 안내 + "내일 아침에 만나요"만(푸시는 검증 후) |

🔴 **Phase 0 → 1 게이트**
- [ ] 스파이크① 승자 표현 방식 **1개 확정** (데이터의 '분위기 표현' 정의가 여기서 박힌다 — 이후 바꾸면 라이브러리 전체 재작업)
- [ ] 커버리지 매트릭스 숫자 확정 (몇 장·어느 셀)
- [ ] 규제 최소 요건(동의·보관·모더레이션) 확정
- [ ] 위 정책표에서 **Phase 1에 필요한 값**(가입 시점·지역·날씨 탭·톤·체감온도 식) 결정 완료

> ⚠️ Phase 1의 '스파이크 무관' 부분은 이 게이트를 **기다리지 않고** 동시 착수해도 된다. 게이트가 막는 건 Phase 2(추천 엔진)뿐이다.

## Phase 1 — 앱 골격 + 스파이크 무관 코어 (스파이크와 병렬 착수)

**목표:** 추천 엔진만 빼고 앱 전체를 완성한다. 끝나면 "추천만 꽂으면 되는 상태". 스파이크 결과가 필요 없다.

### 1A. 기반 — 앱 뼈대 · 데이터 계층 · 인증
- PWA 셸, **2탭 내비게이션**(코어 / 날씨) — PRD FR-18
- 데이터 모델(PRD §9 = DM2) 테이블을 논리 모델대로 생성
- 게스트 진입 → **저장 시 가입** 전환 · 본인 데이터 권한 분리(DR-3)

🔴 게이트: 앱이 뜨고 · 게스트로 진입되고 · 빈 2탭이 전환되고 · 데이터에 읽고 쓰고 · 가입/로그인 왕복이 된다.

### 1B. 날씨 파이프라인 (end-to-end, 독립)
- 위치 → 기상청 **격자(nx,ny) 변환**, 권한 거부 시 **동 단위 수동 선택**(기본 서울) — FR-8
- 기상청 단기예보 호출 → `weather_cache` 저장 → **체감온도 밴드 + 강수 단계** 산출(PRD §8 규칙표 그대로)
- 체감온도 식 확정(습도 +1밴드 보정 준수) — 🔬 §16-5
- **날씨 탭**(미니멀): 오늘 한 줄 번역 + 시간별 강수/기온 + 행동 조언 + 내일 한 줄
- 코어 탭 헤더 **날씨 배지**

🔴 게이트: 실제 오늘 서울 날씨로 **체감온도 밴드·강수 단계가 규칙표대로** 나온다 · 기상청이 죽어도 캐시로 마지막 값이 뜬다(FR-9) · 날씨/격자 로직 테스트 통과(NFR-6).

### 1C. 온보딩 취향 퀴즈 (UI + 저장)
- 3문항(무드·색·TPO) — PRD FR-1 · (스파이크① 결과에 따라 앵커룩 사진 문항 추가 여부 결정)
- 답을 프로필에 저장 · **취향 프로필 산출은 Phase 2에서 연결**(지금은 답만 저장)

🔴 게이트: 퀴즈 완료 → 무드·색·TPO가 프로필에 저장 · **90초 내 완료**.

### 1D. 참고사진 업로드 (선택, 임베딩 제외)
- 업로드 UI + **"사진 없이 취향으로" 경로 항상 존재**(FR-3)
- 클라이언트 정규화·압축·HEIC 변환(NFR-5) · **사전 모더레이션**(FR-5, RG-3)
- **24h 후 원본 삭제** 정책 배선(표현 산출은 Phase 2)

🔴 게이트: 사진 올리면 검수 통과분만 저장 · 부적절물 거부 · 스킵 경로 동작.

### 1E. 저장 루프 + 계측 골격 + 카피
- 탭 저장 → 토스트 → **저장 목록**(코어 탭 내) — FR-15,16
- **코어 퍼널 이벤트**(오픈→퀴즈→결과→저장) 지금부터 심기 — PRD §4
- 카피 덱(다정한 친구 톤) 적용

🔴 게이트: (더미 카드로라도) 저장→토스트→목록 재열람 동작 · **퍼널 이벤트가 실제로 기록**된다.

🔴🔴 **Phase 1 → 2 게이트 (종합)**
- [ ] 온보딩부터 '결과 자리'까지 클릭이 **끊김 없이 흐른다**(추천 내용만 비어 있음)
- [ ] 날씨가 실측으로 **밴드·강수로 정확히 변환**된다
- [ ] 데이터·인증·저장·계측이 모두 살아 있다
- [ ] = **"추천 엔진만 꽂으면 되는 상태"**

## Phase 2 — 추천 엔진 + 라이브러리 (스파이크① 확정 + Track B 시드 필요)

**목표:** 제품의 심장을 켠다. 코어 루프가 실제 데이터로 끝까지 돈다.

> 착수 조건: Phase 0 게이트 통과(표현 방식 확정) **AND** Track B에서 시드 50~100장 적재 완료.

### 2A. 라이브러리 적재 파이프라인 (오프라인 배치 · AP-2)
- 시드 사진 → **라이선스 출처 기록(필수, DR-2)** → 비전 LLM 메타 태깅(분위기·색·격식·온도밴드·rain_ok·아이템) → **표현(임베딩) 산출**(스파이크① 승자 모델) → 저장(노출 가능 표시)
- 이미지 다중 해상도/썸네일(NFR-5)

🔴 게이트: 시드가 **커버리지 매트릭스 최소 셀**을 채운다 · 모든 사진에 라이선스 출처 + 메타 + 표현이 붙어 있다.

### 2B. 추천 경로 (서버 · 두-갈래 AP-1)
- 질의 결정(참고사진 있으면 그 표현, 없으면 취향 프로필 — 어느 쪽 썼는지 기록)
- **①하드필터 → ②분위기 유사도 랭킹 → ③MMR 3장 → ④결정론 이유 문장** (PRD §7 순서 고정)
- **안전빵 1장 보장** · **최근 노출 반복 방지**(FR-17 이력) · **리롤 1회**
- **빈손 방지 폴백**(온도밴드 ±1 완화 → 그래도 부족하면 솔직 안내) — FR-14
- 파라미터(후보 수·유사도 임계·다양성 강도)는 스파이크① 후 튜닝(🔬 §16-3, 임의 고정 금지)

🔴 게이트: 실제 오늘 날씨 + 취향/참고사진으로 **3장이 뜬다** · 같은 입력=같은 이유(재현, FR-13) · 하드필터가 부적합 사진을 **실제로 제외** · 3장이 서로 다르다 · 후보 0건에서도 화면이 안 깨진다.

### 2C. 결과 화면 완성 + 취향 프로필/참고사진 연결
- 코디 카드(사진·이름·태그·이유·아이템·하트) — FR-12
- 온보딩 퀴즈 답 → **취향 프로필 산출**(스파이크① 확정법) 연결
- 참고사진 → **표현 산출** 연결(24h 원본 삭제 실동작)
- 근거 라인('{무드}×{색} 취향 × 오늘 날씨로 골랐어요')

🔴 게이트: 신규 유저가 **퀴즈만으로도, 참고사진으로도** 각각 그럴듯한 3장을 받는다.

🔴🔴 **Phase 2 → 3 게이트 (종합)**
- [ ] 온보딩 → 오늘의 3코디 → 저장 **코어 루프가 실제 데이터로 끝까지 돈다**
- [ ] 매칭이 "오, 내 취향이네" 수준인지 **내부 눈검사 통과**(스파이크① 기준 재확인) — 이게 제품의 상한이므로 여기서 약하면 3으로 넘어가지 말고 표현/파라미터를 다시 본다

## Phase 3 — 하드닝 · 폴백 · 규제 (출시 차단 요건)

**목표:** 실사용에서 안 깨지게 하고, 법적으로 켤 수 있게 한다.

| 항목 | 내용 | 근거 |
|---|---|---|
| 3A 엣지케이스 4종 | 후보 3장 미만 / 위치 거부 / 기상청 다운(캐시 6h+지연 배지) / 참고사진 부적절 — 각각 폴백대로 | FR-14, GAP |
| 3B 성능 예산 | 오픈→3코디 목표(권고 p95<2.5s): 날씨 캐시 웜 + 격자별 후보풀 사전계산 + 이미지 CDN·프리로드 | NFR-1 |
| 3C PWA 하드닝 | HEIC·홈화면 추가 안내·safe-area | NFR-4 |
| 3D 규제(**출시 차단**) | 동의·개인정보처리방침·보관기간 고지 · 업로드 모더레이션 실동작 · 라이선스 출처 보존 · (AI 생성 쓰면) 표기 | RG-1~5 |
| 3E 비용 가드레일 | 레이트리밋·비용 상한/알림 · 무료 티어 유지 | NFR-2 |

## Phase 4 — 검증 출시

**목표:** 가설을 실제 유저로 시험한다.

- Track B 라이브러리가 **목표 규모(~700 or 매트릭스 최소)** 도달
- 시드 유저 모집(서울 20대 여성 30~50명)
- **4주 측정** — 북극성 = **D1 아침 트리거 리텐션**, 프록시 = 저장률·D7 재오픈(PRD §4)

🔴 게이트(검증 성공 판정): 착수 전 확정한 성공선 도달 여부(🔬 §16, 예: 저장률≥35%·D7≥20%). 성공 시에만 Phase 2+(네이티브·습관루프·소셜·커머스) 재검토 — 그 전엔 🚫.

## Track B (병렬) — 라이브러리 콘텐츠 수급

> 신모델 **최대 리스크 2번**(콜드스타트). 엔지니어링이 아니라 **콘텐츠 수급**이라 Phase 0부터 따로 굴린다.

| 단계 | 내용 | 게이트 |
|---|---|---|
| B1 | 커버리지 매트릭스(=스파이크②) | 셀별 최소 장수·총 규모 숫자 확정 |
| B2 | 소싱(예산 최소: 오픈 라이선스 + **AI 생성 파일럿**) | AI 생성물의 **유저 반응 파일럿 관문 통과**(신뢰 문제 확인) |
| B3 | **시드 50~100장 먼저** → 목표 규모 확장 | 시드가 Phase 2 착수를 언블록 |
| B4 | 각 사진에 라이선스 출처 + 메타 태깅 + 표현 | 모든 사진이 적재 파이프라인(2A)을 통과 |

- B3 시드가 **Phase 2 착수 게이트**, B의 목표 규모 도달이 **Phase 4 출시 게이트**.

## 리스크 · 주의

- **가장 큰 재작업 위험 = 표현 방식(스파이크①)을 성급히 고정하는 것.** 이걸 바꾸면 라이브러리 전체를 다시 표현해야 한다(PRD AP-2/DEP). Phase 2 착수 전 반드시 확정.
- **매칭 품질이 제품의 상한.** Phase 2 종료 눈검사에서 "내 취향이네"가 안 나오면, 화면을 더 예쁘게 만들지 말고 표현/파라미터로 되돌아간다.
- **라이브러리가 진짜 초기 투자처.** 서버비가 아니라 콘텐츠. Track B가 늦으면 앱이 다 돼도 검증을 못 한다 → Phase 0부터 굴린다.
- **🚫 되살리기 금지(PRD §17):** 배경제거·의류 세그멘테이션·옷 조각 태깅·조합 엔진·요청마다 LLM 이유생성·스크래핑·소셜/커머스. "개선"으로 다시 넣지 않는다.
- **PRD와의 동기화:** 이 계획이 PRD의 🔬를 앞서 정하면, `CLAUDE.md`·`문서_정본지도`·PRD를 **먼저 갱신**하고 계획을 뒤따르게 한다.
