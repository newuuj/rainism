# A. 옷장 — 등록 · 디지털화

## A1. AI 옷 태깅 (사진 → 카테고리·색·소재·핏)

**① 구현 기술**
- 비전 LLM(VLM: 사진 보고 속성 뽑는 AI) — Gemini Flash급, **장당 $0.001~0.004**(Flash-Lite는 $0.0002~0.001). JSON 스키마로 출력 형식 강제 + 한글 taxonomy(분류 사전).
- 카테고리·대분류 색은 자동으로 실용 수준(Gemini 2.0 Flash macro-F1 ~57%).

**② 현재 제약**
- **소재·핏이 최대 약점**: 소재 exact-match 63%(최고 파인튜닝 모델도), 색 exact-match 11.6%(조명이 픽셀 색을 통째로 바꿈), 형태 F1 ~70%/패턴 55%/소재 49%(WACV 2026 벤치).
- **과검출**(없는 속성도 지어냄)이 최대 실패 모드 → 저신뢰 속성은 빈칸으로 두고 **사람이 수정(HITL)** 하는 게 정답.
- 유저 실사진(구겨짐·역광·착용샷)은 카탈로그 이미지보다 정확도 하락.

**③ 유사 서비스**
- **에이클로젯**: 카테고리·색·계절·패턴 자동 입력. **GetWardrobe**: "초 단위 카탈로깅" 주장하나 색을 제한된 선택지에서 수동 재지정해야 하는 불만. **Whering**: 자동 태깅 후 롱프레스 일괄 수정. → 업계 공통 = 자동 태깅 + 유저 수정.
- 향후: **Fashion Florence**(Florence-2 소형 모델을 LoRA로 파인튜닝) — 소재 exact-match 63% vs GPT-4o-mini 43%, **한계비용 $0**. 유저 수정 데이터가 쌓이면 여기로 전환하는 게 로드맵.

---

## A2. 배경제거 (누끼 따기)

**① 구현 기술**
- **온디바이스 무료**가 표준: iOS Vision(VNGenerateForegroundInstanceMaskRequest) / Android ML Kit Subject Segmentation(~200ms, 무료, 완전 온디바이스).
- fallback: remove.bg API($0.11~0.23/장). 스케일 시 서버 SAM(Segment Anything) 셀프호스트로 한계비용 ~0원.

**② 현재 제약**
- 온디바이스는 **"전경 피사체 ↔ 배경" 분리**이지 의류 파싱이 아님(→ A3 참조).
- 실패 모드(Alta가 문서화): 흰 벽 앞 흰 운동화, 동색 배경(파란 담요 위 파란 스웨터), 반사 표면·주얼리. ML Kit은 **베타**(호환성 변경 리스크), 정지 이미지만(영상 X).

**③ 유사 서비스**
- **Alta**: SAM 셀프호스트로 2천만 장 처리, 외부 API 비용을 0으로. **에이클로젯**: 쇼핑몰 상품컷처럼 보정. **Cladwell**: 배경제거가 "제대로 작동 안 함" 불만. **Whering**: 배치 업로드해도 크롭은 장당 수동(→ "이틀 노동").

---

## A3. 멀티아이템 등록 (한 컷에 여러 벌)

**① 구현 기술**
- **플랫레이(침대에 펼쳐놓고 촬영)**: 옷이 물리적으로 떨어져 있어 온디바이스 인스턴스 마스크로 벌 단위 분리 가능. **가장 현실적인 마찰 축소 경로.**
- **착장/거울샷**: 서버 비전 LLM 바운딩박스 크롭 필요(장당 ~$0.002).
- 미래: **SAM3**(2025.11, "카디건" 같은 명사구 프롬프트로 한 장에서 여러 아이템 분리) — 서버 모델.

**② 현재 제약 (중요)**
- **거울샷은 온디바이스로 옷별 분리 불가** — 옷 입은 사람 전체가 하나의 피사체로 잡힘. (예전 "온디바이스 한 컷→여러 벌"은 플랫레이 한정)
- 겹친 옷·어두운 배경 실패. 사람 입은 사진으로 학습한 파싱 모델도 플랫레이에선 mAP 45~50점 붕괴(도메인 갭). **비디오 옷장 스캔은 아직 상용 사례 없음**(선점 여지).

**③ 유사 서비스**
- **DRESSED**: 플랫레이 멀티스캔, 아이템당 15~20초, 풀옷장 10~20분(경쟁앱 30~60분의 절반). **에이클로젯 Smart Detector**: 거울셀카 자동 분리(서버, 누적 9천만 벌). **홈 인벤토리 앱**(ShelfLily 등): 방 사진 1샷 → 20개 물품 추출.

---

## A4. 고스트 옷장 (사진 없이 탭으로 등록)

**① 구현 기술**
- 한국 20대 공통템 프리셋 카탈로그(자체 제작 일러스트 + 라이선스 피드) + 유저가 가진 걸 탭 + 색칩. **사전 확정 메타데이터라 태깅 비용 0, 오류 0.**
- 이론적 근거: training-free 온톨로지 프라이어(도메인 지식을 규칙으로 박은 것)가 콜드스타트에서 밑바닥 학습보다 sample-efficient.

**② 현재 제약**
- 프리셋은 아키타입(대표 원형)이라 실물 핏/패턴이 다름(같은 흰티도 크롭/오버핏이 궁합 뒤집음) → **패턴 축 추가 + 실사진 교체 유도** 필요.
- **재고량 자체는 못 늘림** → 신선함의 근본 병목은 못 푼다(B5 참조).

**③ 유사 서비스**
- **Cladwell**: 스톡 DB에서 "내 옷과 비슷한 것 선택"이 기본 등록 경로. **Whering**: DB에서 비슷한 아이템 선택을 1급 등록 경로로 인정. **Stylebook**: 기본템 카탈로그(Import Wardrobe Basics) 베타. → 사진 없는 등록은 이미 검증된 방식.

# B. 오늘의 3코디 — AI 코디 엔진

## B1. 코디 생성 4단 파이프라인

**① 구현 기술**
- **하드필터**(체감온도·강수·격식으로 못 입을 옷 컷, 규칙/CSV) → **소프트스코어**(3색 규칙·궁합·추구미 가중치) → **LLM 재랭킹**(소수 후보만 재정렬·설명, 출력을 보유 옷 ID로 스키마 강제) → **MMR 다양성**(3개를 서로 다르게).
- 비용: 성긴 옷장은 하드필터 후 후보 수십 개 이하 → 유저당 LLM 1콜(~$0.001~0.004). DAU 1만이어도 하루 $10~40.

**② 현재 제약**
- **성긴 10벌은 하드필터 후 실현 조합 2~3개** → 다음날 같은 날씨면 거의 동일 세트 = 뻔함. (재고가 진짜 병목, 메타데이터 아님)
- 손규칙 궁합표는 조합폭발로 유지 불가("값싼 규칙" 아님). LLM 순수 궁합 판정 약함(빈칸채우기 29%) → **재랭킹·설명 용도로만**.
- **예보구역당 1회 캐시 불가** — 개인화(옷장·취향·상황)가 유저 단위라 캐시하면 개인화가 지워짐. 3코디는 유저 요청마다 온디바이스 결정론 엔진으로.

**③ 유사 서비스**
- 업계 최신 시스템(Loom 등) = **하드필터→학습 스코어링 2단 깔때기** (rainism 4단이 이 표준을 따름). **Stitch Fix**: 사람 스타일리스트 + 알고리즘. **Cladwell/Whering**: 랜덤 셔플이라 "상의+상의" 조합 오류·"어떤 날은 0개" 불만. **Pureple**: 슬롯 못 채우는 불만.

---

## B2. 궁합 판정 (뭐랑 뭐가 어울리나)

**① 구현 기술**
- **3색 팔레트 궁합**(각 옷을 대표 3색으로 표현) — 이것만으로 궁합 AUC 0.90(딥러닝 이미지 특징을 능가). **사진 없는 옷장의 결정적 근거.**
- + 카테고리 함께-입음 규칙. 향후: 프리트레인드 임베딩(Marqo-FashionCLIP)으로 LLM 없이 코사인 거리 궁합.

**② 현재 제약**
- 학습기반 궁합(type-aware embedding/GNN)은 **Polyvore 6.8만 코디 라벨 + GPU 전제** → 1인·데이터0팀 진입 불가. 색만 쓰면 패턴 정보 손실.

**③ 유사 서비스**
- **Polyvore 계열 연구**(궁합 학습의 표준 데이터셋), **Style2Vec**(같은 코디에 함께 등장한 아이템으로 라벨 없이 궁합 학습 — UGC 쌓이면 공짜), **Stitch Fix**.

---

## B3. 설명가능성 ("왜 이 코디?")

**① 구현 기술**
- 하드필터가 **실제로 사용한 결정값**에서 템플릿 생성 → "체감 31도라 린넨, 오후 약속이라 격식 업". **환각 불가·비용 0.**

**② 현재 제약**
- LLM 자유 생성 설명은 환각(없는 사실 지어냄) 위험 → 규칙 템플릿이 정답. 소재를 빈칸으로 두면 소재 기반 설명 불가(비 오는 날 린넨 판단 못 함) → 필요 시점에 맥락 질문으로 회수.

**③ 유사 서비스**
- **경쟁앱 대부분 설명 없음** → "그냥 랜덤이네"가 공통 불만. = rainism 차별점.

---

## B4. 추구미 온보딩 (취향 → 엔진 파라미터)

**① 구현 기술**
- 4지선다 조합형 퀴즈(CBC/직교설계, 10문항 상한) → 스타일 선호 벡터(초기 프라이어). 이후 implicit 신호(탭/착용)로 갱신. Calibrated Recommendation으로 3코디 믹스 비율을 취향 비율에 보정.

**② 현재 제약**
- 설문은 약한 신호이고 빨리 낡음 → **갱신 루프 없으면 취향이 초기 답변에 고착.**

**③ 유사 서비스**
- **Spotify**: 아티스트 3개 선택(임계값)으로 홈 즉시 채움. **Netflix**, **Stitch Fix Style Shuffle**: 틴더식 스와이프로 취향 학습.

---

## B5. 다양성 · 트렌드 신선함 ("안 뻔하게") — 🔴 최대 난제

**① 구현 기술**
- **MMR**(3개를 서로 겹치지 않게) + 탐색 슬롯 1개(MVP는 규칙 변주 SMMR → 착용 로깅 후 컨텍스추얼 밴딧으로 승격).
- 트렌드: 이미지 없이 **속성 가중치 시계열**로 인코딩(버건디↑를 JSON으로). 합법 소스 = Google Trends API(2025 알파) + 네이버 데이터랩 + 국내 공개 랭킹.

**② 현재 제약**
- DPP(더 정교한 다양성)는 계산 O(n³)로 과함. 순진한 다양성은 오히려 만족도↓(유튜브 A/B).
- **트렌드 가중치는 가진 옷만 재랭킹** — 옷장에 버건디 없으면 부스트 대상 없음. → 신선함을 "가중치"가 아니라 **조합 신선함 + 설명 카피 + gap-filler로 재고 확충**으로 재정의해야 함.
- 조합 문법 트렌드(발레코어·레이어링)는 아이템 속성 벡터로 표현 불가.

**③ 유사 서비스**
- **YouTube**(DPP 다양성), **Heuritech**(트렌드를 속성 시계열로 예측), **KERN**(패션 요소별 트렌드 forecasting). 트렌드=속성 가중치 표현은 검증됨, 수집만 합법 소스로.

# C. 날씨

**① 구현 기술**
- **기상청 공공 API**(무료): 단기예보(시간별 강수확률 POP·기온), 초단기실황·초단기예보(1시간 갱신), 과거관측 ASOS. 체감온도 계산 → **규칙표(CSV)로 슬롯·소재 매핑** → 사람 말로 번역("체감 31도, 오후 소나기 60%"). 위치 = 행정동(읍·면·동, 격자 5km) 단위.

**② 현재 제약**
- 초단기예보는 **1시간 주기 갱신**이라 "하루 1회 캐시"는 곧 낡음(stale). 예보 빗나가면 앱을 원망(트리거 피로 & 날씨 누명). 체감온도는 개인차(체질) → 개인 오프셋으로 천천히 수렴 필요.

**③ 유사 서비스**
- **Weather Fit·날씨날씨·오늘뭐입지**: 기온→일반 옷차림(캐릭터/텍스트), 내 옷 아님. **Alta**(TIME 최고발명)조차 날씨 반영이 최대 불만("호주 더위에 따뜻한 옷"). **Cladwell**: 38도에도 가디건(하드필터 부재). → **날씨 로직 깊이가 실제로 비어 있는 차별 지점.**

# D. 피드 — OOTD 소셜 — 🔴 후순위(소셜 마지막)

**① 구현 기술**
- UGC 업로드 + 그날 기온·강수 **자동 태그**(기상청 + 촬영 시각/위치). 착장샷→아이템 분리(서버). NSFW 자동 필터 + 신고 큐 + 24시간 대응.

**② 현재 제약**
- **소셜 콜드스타트**("피드 유령도시" — 유저 없으면 콘텐츠 없음). **2026.7.1 이미지 모더레이션 규제**(불법촬영물 필터링 의무가 이미지로 확대, 즉시 대상은 아니나 앱스토어가 UGC 앱에 자체 모더레이션 요구). 얼굴 = 초상권·민감정보 → 기본 비공개·크롭.

**③ 유사 서비스**
- **무신사 스냅**(누적 100만+ 콘텐츠, 적립금·이벤트로 공급 인위 제작). **오늘의집**(첫 사진 1,000P, "집들이" 대신 경량 기여 단위). **웨디**(크리에이터 코디 큐레이션). → 콜드스타트 정석 = T-30 씨딩 + 프로 크리에이터 믹스 + 인센티브.

# E. 습관화 — 알림 · 위젯

**① 구현 기술**
- 홈 위젯 / **잠금화면 위젯**(iOS WidgetKit) — "오늘의 3코디" 카드. 아침 트리거 푸시(행동 트리거 + 개인 타이밍). 계정 없이도 **익명 로컬 푸시**로 내일 아침 브리핑 발송.

**② 현재 제약**
- iOS 잠금화면 위젯 인터랙션 = **탭(딥링크)만** 가능. 푸시 남발 = 소음 → 삭제. 위젯을 유료 벽 뒤에 두면 습관 루프 자체가 죽음.

**③ 유사 서비스**
- **Weather Fit**(위젯이 코어, 4.6★/리뷰 3,700): "앱 안 열고 위젯에서 답". **캐시워크**: 잠금화면에서만 수확 → 폰 켤 때마다 접점. **Duolingo**: 스트릭 + 면제권 2개 선지급.
