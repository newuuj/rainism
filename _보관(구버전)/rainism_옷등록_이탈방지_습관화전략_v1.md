# rainism — 옷 등록 이탈 방지 & 습관화 전략 v1

> **과제:** "사람들이 옷 사진을 직접 찍는 구간에서 탈주하지 않고, 계속 쓰는 습관을 만드는 법."
> **결론 한 줄:** 촬영을 **강요하지 말고 대부분 건너뛰게** 하고(0벌에서도 가치 선지급), 꼭 찍어야 할 때는 **10배 빠르고 예쁘게**, 그리고 등록을 **일회성 프로젝트가 아니라 매일 아침·저녁 루프의 부산물**로 바꾼다.
>
> *작성 2026-07-08 · 5각도 웹 리서치(78건) + 아이디어 27개 발산 → 16개 통합 → 적대적 2인 검증 기반*
> *짝 문서: [rainism_기획리서치_종합노트_v1.md](rainism_기획리서치_종합노트_v1.md)*

## 0. 한 장 요약 (먼저 읽으세요)

1. **문제는 "사진 찍기 싫다"가 아니다.** 진짜 벽은 세 개다 — ① **시작 자체를 안 함**(Indyx: "중도 포기보다 아예 시작 안 하는 사람이 압도적"), ② **내 사진이 못생겨서**(파워유저들이 촬영 대신 쇼핑몰 상품컷을 스스로 찾아 씀), ③ **보상이 나중에 옴**(입력은 지금, 코디는 12벌 뒤). 이 셋을 각각 다른 무기로 친다.
2. **첫 세션은 촬영 0회로 통과시킨다.** 추구미 퀴즈 → **고스트 옷장**(공통템 탭 체크인 90초) → 그 자리에서 **프리뷰 코디 1개** → "내일 아침 첫 3코디" 예약. 가입은 뒤로(Duolingo가 이 순서로 DAU +20%).
3. **꼭 찍을 땐 "여름옷 개시식" 4컷 플랫레이 5분.** 침대에 펼치고 4번만 찍으면 12~15벌(DRESSED 실측 3~5분, 기존 앱은 24분). 매 벌 **3초 안에 태그+궁합 코디** 반환 → 등록이 노동이 아니라 "내 옷 조회"가 됨(Vivino 원리).
4. **등록을 매일 습관에 녹인다.** 아침에 코디 소비 → **저녁에 "옷 반납" 1탭**(착용 로그 + 안 넣은 옷 1장 등록) → 다음 아침 리빌. 옷장이 주당 5~10벌씩 저절로 자란다.
5. **북극성 지표는 "D1 트리거 리텐션"**(다음날 아침 코디를 실제로 탭했는가) 하나. 여기에 도달시키는 활성화 공식 가설 = **"48시간 내 상의 4 + 하의 3 등록 & 다음날 아침 코디 1탭."**
6. **P0(첫 여름 출시 필수 4개):** 고스트 옷장 · 여름옷 개시식 · 3초 리턴 SLA · 저녁 반납 루프(최소버전).

## 1. 문제의 재정의 — "왜 찍다 나가는가"

### 표면 vs 진짜 원인

| 우리가 오해하기 쉬운 것 | 리서치가 말하는 진짜 원인 | 근거 |
|---|---|---|
| "촬영이 귀찮아서 나간다" | 대부분은 **첫 촬영을 시작조차 안 한다** — 이탈의 주전장은 '중간'이 아니라 '첫 10초' | Indyx how-it-works: "중도 포기하는 사람보다 아예 시작 안 하는 사람이 압도적" |
| "사진 찍는 게 노동이라서" | 노동의 **절반은 심미 문제** — "내가 찍은 옷 사진이 못생겨서" 안 올린다 | 더쿠 실사용자 "직접 찍는 것보다 캡쳐가 훨씬 깔끔", Indyx 스타일리스트는 Google Lens로 상품컷을 찾아 올림 |
| "배경제거·태깅 기술만 좋으면 됨" | 체감 마찰의 본체는 촬영이 아니라 **AI가 틀린 걸 고치는 시간** | GetWardrobe·에이클로젯 리뷰: 자동 감지된 색/소재를 일일이 수정하는 게 최대 불만 |
| "12벌 다 넣게 만들면 됨" | 12벌은 **보상이 안 보이는 구간** — 다 넣어도 "왜 매일 열지?"가 없으면 데이터 묘지 | 종합노트 §4 '카테고리의 저주' |

### 퍼널 지도 — 어디서 누가 왜 떨어지는가

```
 다운로드 ─▶ 첫 실행 ─▶ 첫 사진 ─▶ 12벌 ─▶ D1 아침 ─▶ D7 ─▶ 계절 절벽
              │           │          │        │          │        │
   허영지표    가입 강요   "찍기 싫다  "보상이  "다음날    습관     여름 온보딩
   (의미없음)  = 이탈      + 내 사진   안 보임"  안 열면     자동화   유저가 겨울옷
                          못생김"              끝"        전 이탈   미등록→이탈
```

- **첫 실행:** 가입 화면·긴 온보딩·권한 폭탄에서 샌다. (해법 축 A)
- **첫 사진:** 촬영 진입 장벽 + "내 사진 못생김". 여기가 최대 출혈점. (해법 축 A·B)
- **12벌 구간:** '12벌의 벽' — 보상이 안 보여 지침. 에이클로젯 유저당 평균 등록이 **정확히 약 13벌**에서 정체(700만 유저·9천만 벌). (해법 축 C)
- **D1 아침:** 다음날 안 열면 사망. 생존지표 그 자체. (해법 축 D)
- **D7 & 계절 절벽:** 습관 자동화까지 중앙값 **66일**(Lally 2010)이라 한 시즌 습관도 환절기 재등록에서 끊긴다. (해법 축 D)

> **정량 감각:** Indyx 실측 — 셀프 등록 **벌당 2분**, 평균 옷장 166벌 = 5.5시간짜리 비현실적 과제. 그래서 '전체 등록'을 목표로 잡는 순간 진다. **여름 데일리 12~15벌 서브셋**만 요구하는 게 정답.

## 2. 전략 4축과 해법 카드

발산된 15개 생존 아이디어를 **4개 전략 축**으로 묶었다. 각 카드에 우선순위(P0=첫 출시 필수 / P1=초기 확장 / P2=네이티브 이후)를 붙였다.

### 축 A — 첫 촬영을 건너뛴다 (0벌에서 가치 선지급)

> **핵심 원리:** 시작 문턱을 '촬영 0회'로 내린다. 부여된 진행 효과(세차장 실험: 스탬프 2개 미리 찍으면 완료율 19%→34%)와 "소비가 창작보다 먼저"(TikTok) 순서 뒤집기.

#### 🟥 P0 · 고스트 옷장 — 공통템 탭 체크인 90초
- **무엇:** 추구미 퀴즈 직후, 한국 20대 여성 공통템 24~60개(자체 제작 플랫레이 일러스트) 그리드에서 **가진 걸 탭 + 색칩 1탭**(벌당 탭 2회). 10~12벌을 90초~3분에 담으면 "내일 아침 6:30, 첫 3코디" 카운트다운으로 세션 완결. 이후 코디에서 고스트 아이템은 반투명 실루엣 → **[내 옷으로 바꾸기]** 배지로 하루 1벌씩 실사진 교체 유도.
- **왜 통하나:** Cladwell이 "스톡 DB 매칭 등록만으로 날씨 3코디 앱" 성립을 이미 증명. Anki 커뮤니티의 결론이 핵심 — **소유감은 처음부터 만드는 게 아니라 "검증된 프리셋을 받아 고치면서" 생긴다.** 촬영 0회라 시작 문턱이 가장 낮고(Indyx 관찰 대응), 프리셋은 카테고리·색·소재·핏이 사전 확정된 정답 데이터라 오히려 비전LLM 태깅(소재 49% 오류)보다 품질이 높다.
- **리스크 & 대응:** 고스트 비중이 오래 높으면 "내 옷 실감" 부재로 웨디식 괴리감 → **"비슷한 옷 기준이에요" 라벨 강제** + D7 교체율을 활성화 지표로 관리(3벌 미만 코호트는 실사진 촬영 유도로 폴백). 뻔한 조합 불신 → 색칩 외에 **핏 토글(크롭/레귤러/롱) 1탭** 추가로 고스트 상태에서도 변별력 확보.
- **난이도:** 낮음~중간 · **검증 임팩트:** 4.5/5 (최고점)

#### 🟨 P1 · 선(先)브리핑 — 가입도 옷도 0에서 시작하는 날씨 코디
- **무엇:** 첫 실행 시 가입 없이 **위치 권한 1개만**(거부 시 서울 폴백) → 3초 뒤 "오늘의 브리핑": 기상청 수치 문장("체감 31도, 오후 4시 소나기 60% — 린넨과 통바지의 날") + 자체 제작 코디 3장. 각 코디 아래 아이템 칩을 "갖고 있으면 탭하세요"로 첫 입력을 소비 속에 숨김.
- **왜 통하나:** "갖고 있으면 탭"은 **결정이 아니라 인지(recognition)** 행위라 '결정 피로' 페르소나와 충돌하지 않는다. Duolingo가 가입을 뒤로 미뤄 DAU +20%(단 소프트월→하드월 순서가 조건). Alta조차 날씨가 최대 불만이라 "기상청 수치 브리핑"은 0벌에서도 성립하는 진짜 차별점.
- **리스크 & 대응:** "그냥 날씨 앱/웨디 아류"로 오인 → 첫 브리핑 하단에 **"네 옷을 채울수록 이 코디가 네 옷장 사진으로 바뀝니다"** 한 줄로 코어 가치를 선언. 가입(하드월)과 알림 권한을 분리해 계정 없이도 익명 로컬 푸시로 내일 아침 브리핑 발송.
- **난이도:** 중간 · **임팩트:** 4/5

#### 🟨 P1 · 주문내역 스크린샷 던지기 — 이메일 포워딩의 한국형 재설계
- **무엇:** 등록 허브 → [쇼핑앱에서 가져오기] → 무신사·지그재그·에이블리·쿠팡 아이콘 → "주문내역 열기 → 캡처 2~3장 → 공유시트/갤러리에서 rainism". VLM(장당 ~$0.003)이 품명·색·사이즈·썸네일 파싱 → **"지금도 입는 옷만 남겨줘" 체크리스트**로 반환. 이메일·계정 연동·자동 로그인 일절 없음.
- **왜 통하나:** Indyx식 이메일 포워딩은 한국에서 구조적 실패 — 주문 알림 표준이 **카카오 알림톡/SMS**이고 소비자용 주문 API는 전무, 마이데이터도 '여성 의복' 수준 카테고리만 준다. 유저가 스스로 캡처해 제출하는 게 유일한 합법 경로이며, **잡코리아 v 사람인 4.5억 배상 판례**가 자동 수집 대행을 배제할 근거. 쇼핑앱 품명("린넨 와이드 슬랙스 베이지 M")은 사진 태깅이 절반 틀리는 소재·핏을 **텍스트로 더 정확히** 준다.
- **리스크 & 대응:** 버린 옷·환불 혼입(쓰레기 데이터) → **주문일 파싱해 최근 12개월만 기본 선택**, 항목마다 주문일 배지. 상품 썸네일은 저작권 이미지 → **비공개 옷장 전용, 피드 노출 전면 차단** + 7~30일 내 "내 사진으로 바꾸기" 넛지.
- **난이도:** 중간 · **임팩트:** 4/5

### 축 B — 꼭 찍어야 할 때, 10배 빠르고 예쁘게

> **핵심 원리:** 셔터 횟수를 자릿수로 줄이고(12회→4회), 등록 직후 초 단위로 보상을 돌려준다.

#### 🟥 P0 · 여름옷 개시식 — 침대 위 4컷 플랫레이 5분
- **무엇:** 온보딩을 "옷 등록"이 아니라 **"이번 여름 주전 선수 뽑는 개시식"**으로 프레임: "침대에 이번 주 입을 옷을 펼치세요 — 4번만 찍으면 끝." 오버레이 가이드가 ①상의 4벌 → 셔터 → 온디바이스 인스턴스 마스크로 아이템 카드 팝(카테고리·색 자동, **소재·핏은 공란**) ②하의 3벌 컷 끝나는 순간 **미니 코디 1개 즉석 생성** ③신발 ④아우터/원피스 = 4컷에 12~15벌. 진행바는 퀴즈 답변을 선환산해 **20%에서 시작**. 마지막에 "여름 선발 라인업" 포스터 자동 생성으로 완결.
- **왜 통하나:** DRESSED가 동일 플로우로 **아이템당 15~20초, 12벌 = 3~5분**을 공표(기존 앱 30~60분의 1/5~1/10). 홈 인벤토리 앱의 "선반 1샷 = 20개" 도약이 같은 기술 검증. 숨고 정리수납 평균 **51.7만원·옷장이 최다 요청**일 만큼 "옷장 정리"는 한국인이 돈 내고도 하는 의식 — 등록을 그 의식의 부산물로. "4컷" 청킹은 체크리스트 벤치마크(3~5덩어리 + 진행바 + 축하 = 완료율 배증)와 일치, 2컷째 미니 코디는 IKEA 효과 경계조건("완결 이벤트가 있어야 애착")을 충족.
- **⚠️ 기술 전제(반드시 검증):** 플랫레이는 **옷이 물리적으로 떨어져 있어** 온디바이스 인스턴스 마스킹이 작동한다. 단 겹치거나 어두운 침구+어두운 옷(동색)은 Alta가 문서화한 실패 모드 → **개발 전 킬스위치 테스트**: 실제 자취방 침구 30세트에서 4벌 1샷 분리 성공률 측정, ~70~85% 미만이면 **"2벌 1샷"으로 자동 강등**(의식 프레임 유지, 난이도만 절반). 촬영면은 침대 고정 말고 "밝고 무늬 없는 면 아무거나".
- **리스크 & 대응:** "5분" 약속 못 지키면 역효과 → 카피 숫자는 옷 꺼내기 포함 **내부 실측 P75** 기준으로만. 자취방 좁으면 → "지금 집 아님" 분기로 예약(실행 의도) + 그전까지 "오늘 입은 옷 1벌 즉석 등록"으로 D1 선점.
- **난이도:** 중간 · **임팩트:** 4.5/5

#### 🟥 P0 · 3초 리턴 — 등록을 "노동"이 아니라 "내 옷 조회"로 (모든 등록 경로의 공통 SLA)
- **무엇:** 어떤 경로로든 옷 1벌이 들어오면 **3초 안에** ①고신뢰 태그만(소재·핏은 지어내지 않고 빈칸) ②"지금 옷장 기준 이 옷의 베스트 궁합" 미니 코디 1개 ③"입을 만한 조합 9→27개" 카운터가 튀어오르는 햅틱. 태그 수정은 스킵 가능(나중에 몰아서).
- **왜 통하나:** Vivino는 스캔 1장에 초 단위로 답을 돌려줘 등록을 "데이터 입력"이 아니라 "내 와인에 대한 답"으로 바꿔 **27억 스캔**을 쌓았다. Fetch는 입력 1건당 꽝 없는 즉시 보상. BJ Fogg 데이터상 **행동 직후 축하 생략은 완료율 -50% 요인**. 소재 빈칸은 WACV 실측(소재 F1 49%, 과검출이 최대 실패)의 정답 대응.
- **리스크 & 대응:** 서버 지연으로 3초 못 지키면 보상이 역효과 → **단계적 공개**: 0~1초는 로컬 계산만으로(사진 프리뷰 + 조합 카운터 + 햅틱)을 1차 보상으로 확정, LLM 태그·코디는 스켈레톤 카드에 3~6초 스트리밍. 카운터는 전체 순열이 아니라 **하드필터(체감온도·격식) 통과한 "입을 만한 조합"만** 세어 체감 품질과 일치. 옷 1~2벌 구간은 미니 코디 대신 **"이 옷, 오늘 날씨에 입을 수 있나?" 날씨 판정 카드**로 대체.
- **난이도:** 중간 · **임팩트:** 4/5

#### 🟨 P1 · 찍으면 상품컷으로 바꿔주기 — "내 사진 못생김" 정면 해결
- **무엇:** 옷 1벌 등록 순간 [내 사진] vs [비슷한 상품컷](라이선스 어필리에이트 피드 유사도 매칭) "어느 쪽으로 보관?" 1탭. 매칭 신뢰도 낮으면 비교 화면 자체를 건너뛰고 내 사진으로 조용히 확정.
- **왜 통하나:** 촬영 마찰의 숨은 절반은 심미 문제. 파워유저들의 수동 우회(Google Lens로 상품컷 찾기)를 자동화 → "대충 찍어도 예쁜 옷장". 매칭 데이터는 어필리에이트 gap-filler의 상품-옷장 연결 그래프를 공짜로 축적.
- **리스크 & 대응:** 보세·구제·노브랜드 매칭률 낮음 → 저신뢰 시 비교 화면 숨김 필수. **이 화면에 구매 링크 절대 금지**("결국 쇼핑 앱" 인상 방지). 유사도 검색 인프라 필요 → **P2로 미룰 수 있음**.
- **난이도:** 중간 · **임팩트:** 높음(정식 검증은 세션 한도로 미완, §6)

### 축 C — 등록을 "노동"이 아니라 완결·정체성·게임으로

> **핵심 원리:** IKEA 효과는 "완성했을 때만" 발동(4.6배 가치). 12벌 벽의 정상에 "노력의 결정체"를 놓고, 수정 노동을 게임으로 바꾼다. 한국 20대의 인증·MBTI 공유 문화를 그대로 재사용.

#### 🟨 P1 · 옷장 명함 — 12벌 완성의 산출물을 공유 가능한 정체성 카드로
- **무엇:** 12벌 도달 순간 "여름 옷장 명함" 자동 리빌: ①내 옷 실사 누끼 콜라주 ②AI 한 줄 스타일 진단("실키 미니멀: 무채색 70%, 린넨 파") ③"현재 27가지 조합 보유" ④인스타 스토리 규격 공유 버튼 + 초대 링크. 옷 사진은 기본 비공개, **명함 공유만 명시적 opt-in**.
- **왜 통하나:** 에이블리 AI 프로필이 실증 — "즉시 눈에 보이는 나만의 결과물"이면 한국 20대 여성은 사진 5장+ 업로드도 감수. 스타일 진단 공유는 **MBTI·퍼스널컬러 놀이 문법**과 일치, Duolingo 마일스톤 공유 카드가 일 600만 건 자발 공유. 12벌 전 구간을 "명함 만들기 여정"으로 재프레임.
- **리스크 & 대응:** 누끼·콜라주 퀄리티 낮으면 "못생긴 명함"은 절대 공유 안 됨 → 자동 보정 품질이 성패. 공유 압박 톤 금지(opt-in 철저).
- **난이도:** 낮음 · **임팩트:** 4/5

#### 🟨 P1 · 검수의 게임화 — 등록 땐 "내 옷 맞히기 퀴즈", 습관기엔 저녁 2장 스와이프
- **무엇:** 태깅 검수를 폼 편집이 아니라 게임으로. [등록 직후] 카드 스택 퀴즈 — "AI 추측: 린넨 셔츠, 오버핏! 맞아?" 오른쪽 스와이프=인정, 왼쪽=칩 2탭 정정("AI를 이겼다! +10점"). [습관기] 저녁 반납 직후 딱 2장 — 저신뢰 태그 1개 O/X + 체감 피드백("오늘 조합 어땠어? 더웠어/딱 좋아/추웠어"). **결정적 연출:** 다음날 아침 "어제 '더웠어' 반영 — 오늘은 한 단계 시원한 조합으로 준비했어요."
- **왜 통하나:** 체감 마찰의 본체는 촬영이 아니라 "AI가 틀린 걸 고치는 시간"(GetWardrobe 사례). ESP Game은 이미지 라벨링 노동을 게임 규칙만으로 **13,630명·130만 건 자발 노동**으로 바꾼 원형. 착용 직후 저녁은 유저가 정답(소재 촉감, 실제 더위)을 **몸으로 아는 유일한 순간**. 정정 데이터는 Fashion Florence식 파인튜닝(소재 43%→63%)으로 이어지는 비용·품질 로드맵 자산.
- **리스크 & 대응:** 점수가 실질 보상(코디 품질 체감)과 연결 안 되면 금방 식음 → "태그 확정 시 코디 정확도 게이지 상승" 연결. 매일 질문 반복 = 설문 피로 → **2장 상한 엄수, 미응답 시 다음날 독촉 0**.
- **난이도:** 중간 · **임팩트:** 4/5

#### 🟨 P1 · "내일 아침 예약" 온보딩 — 목표를 12벌이 아니라 시간 약속으로
- **무엇:** 온보딩 목표 화면이 "옷 12벌 등록"이 아니라 **"내일 아침 브리핑 예약하기"**: ①기상 시간 휠 ②내일 일정 칩(수업/알바/약속) ③"브리핑 재료: 상의 2·하의 2·신발 1" 체크리스트(퀴즈 답변이 이미 1칸 선충전). 5벌 차면 "내일 7:30 브리핑 예약 완료"로 완결. 못 채우고 나가면 **"나머지 옷은 언제 찍을래요?"** → "오늘 밤 자기 전 / 일요일 빨래 갤 때" 구체 상황 선택 → 그 시각 리마인드.
- **왜 통하나:** 실행 의도 연구 — "언제·어디서"를 못박으면 실행률 **39%→91%**(메타분석 d=0.65). 진입 임계 5벌은 업계 암묵 합의(10벌 내외)보다 낮은 최저 장벽. 내일 일정 1탭이 다음 아침 푸시("어제 말한 약속용 코디 준비됐어요")라는 트리거를 장전(Hooked 투자 단계).
- **난이도:** 낮음 · **임팩트:** 4/5

### 축 D — 등록을 매일 습관의 부산물로 (일회성 프로젝트 → 루프)

> **핵심 원리:** "한 번에 12벌 몰아넣기"가 아니라 Stylebook 10년차의 결론 = **"입는 날마다 입력하라."** 하루 루프(아침 소비 → 저녁 투자 → 다음 아침 리빌) 안에 등록을 녹인다.

#### 🟥 P0(최소버전) / 🟨 P1(풀버전) · 저녁 "옷 반납" 루프
- **무엇:** 아침 코디 확정 시 잠금화면 위젯이 저녁(예: 22:30) 이후 "반납 모드"로 전환(위젯 하나가 두 얼굴). "오늘 코디 잘 입었어?" 탭 → ①"그대로 입었어" 1탭 → 착용 로그 + 입은 옷 자동 "세탁 중" → 내일 3코디에서 제외(반복감 방지) ②"좀 바꿔 입었어" → 바뀐 슬롯만 탭 → 옷장에 없으면 **그 옷만 1장 촬영** → 옷장 +1. 완료 시 "내일 아침, 이 옷 넣은 코디 준비해둘게요" → 다음날 리빌. **반납 스킵은 무벌점.**
- **왜 통하나:** BJ Fogg 타이니 해빗 공식 그대로 — "옷 벗어 걸 때"라는 기존 물리 앵커 + 30초 이하 행동 + 직후 축하. DRESSED의 "입은 옷 세탁 추적 자동 비활성화"는 코디 반복감을 줄이는 검증된 값싼 규칙. 캐시워크는 수확 행동을 잠금화면 표면에 심는 것만으로 푸시 없이 일일 습관을 만듦. 웨디 리뷰의 **"자기 전에 사용"**이 밤 트리거 슬롯을 실증.
- **리스크 & 대응:** 하루 2접점이 과할 수 있음 → 반납은 **스킵 무벌점 보너스 루프**로, 미반납 시 세탁 상태는 추정. iOS 잠금화면 위젯은 탭=딥링크만 가능(인터랙션 제약).
- **난이도:** 중간 · **임팩트:** 높음(정식 검증 미완, §6)

#### 🟨 P1 · 밤 10시 "내일 코디 예열" — 부족할 때만 "1벌 찍으면 잠금해제"
- **무엇:** 밤 10시 위젯/푸시 "내일 최고 31도·소나기 70%. 3코디 준비 중" — 옷장 충분하면 카드 뒷면만 보여주고 끝. **규칙엔진이 내일 슬롯을 못 채우는 경우에만**(비 예보인데 신발이 샌들뿐) "비 오는 날 신을 신발 1개만 찍어두면 완성 · 30초" → 촬영 → 아침 카드 뒤집기 리빌. **발동 주 2회 상한.**
- **왜 통하나:** 목표 구배(Kivetz 2006) — "1벌만 더" 잔여 프레임은 막판 이탈이 아니라 **가속**을 만든다. Fiorillo(2003, Science)의 P=0.5 불확실성 극대화 — 코디를 아침까지 감추는 리빌이 기대 도파민 보존.
- **리스크 & 대응:** "미완성" 연출 남발 = 양치기 소년 → **실제 슬롯 부족일 때만, 상한**. 슬롯 부족 판정 로직이 틀리면(있는 옷을 없다고) 신뢰 즉사.
- **난이도:** 낮음 · **임팩트:** 미검증(구조 견고)

#### 🟨 P1 · 빈 슬롯 질문 카드 — 등록 안 한 옷을 코디가 먼저 물어보게
- **무엇:** 아침 3코디 생성 시 슬롯을 못 채우면 불완전 코디 대신 **"?" 리빌 카드**: "비 오는 날 신을 샌들이나 레인부츠 있어요?" → ①"있어요" → 색칩만 골라 고스트 등록 + 눈앞에서 코디 완성 ②"없어요" → gap-filler 어필리에이트 상품 2~3개 ③"건너뛰기". **하루 1개 상한.**
- **왜 통하나:** Pureple 교훈 — 슬롯 못 채운 코디는 신뢰 붕괴. 코디를 빼면 Whering "어떤 날은 0개" 불만 재현 → 질문 카드가 제3의 길. "없어요" 경로는 확정된 수익모델(빈 슬롯 gap-filler 어필리에이트)과 정확히 맞물림.
- **난이도:** 중간 · **임팩트:** 미검증(구조 견고)

#### ⬜ P2 · 거울샷 1장 = 착용기록 + 옷장 자동 성장 + 피드 글감
- **무엇:** 하루 한 컷 전신·거울샷 → (a) 착장 자동 분해 → "옷장에 없는 옷 2벌 발견, 넣을까요?" (b) 있는 옷은 착용 기록 (c) 그날 기온·강수 태그 붙은 카드 = 피드 공급원. 매일 1컷이면 옷장이 주당 5~10벌 자람.
- **⚠️ 기술 정정(중요):** 거울샷(착장샷)은 **온디바이스 인스턴스 마스킹으로 옷별 분리가 안 된다** — 옷 입은 사람 전체가 하나의 피사체. 옷별 분해는 **서버 비전LLM 바운딩박스 크롭**(장당 ~$0.002, 기존 태깅 콜에 통합)이 필요. 에이클로젯이 이 방식으로 상용화(9천만 벌)했으나 **P2(네이티브 + 서버 세그멘테이션 이후)**로 미룬다.
- **난이도:** 높음 · **임팩트:** 미검증 · **P2**

#### ⬜ P2 · 새 옷 데뷔 루프 / 계절 이월 크레딧
- **새 옷 데뷔:** 유저는 월 중위 5벌을 산다(Indyx) — 택배 개봉 순간이 최고 등록 동기. "새 옷 왔어요" 퀵액션 → 촬영/캡처 → "내일 3코디 중 1개는 데뷔 코디" 예약. **월 5번의 자연 등록 모멘트가 외부에서 공짜 공급.**
- **계절 이월 크레딧:** 계절 절벽 대응. 기상청 주간예보로 전환 신호 감지 → "가을 옷장 12벌 중 5벌 완성(42%)" 진행바가 이미 찬 상태로 시작(간절기 재사용 아이템 자동 선별) → 신규 촬영은 3~5벌뿐. **여름 옷은 삭제 아니라 "여름 서랍" 영구 보존**(에이클로젯 페이월 역풍 교훈: "투자한 시간 날렸다"). **시즌 2회차에만 작동 → 9월 실험으로 확인.**
- **난이도:** 낮음~중간 · **P2**

### 설계 원칙 3가지
1. **모든 세션을 "완결 이벤트"로 닫는다** — IKEA 효과는 완성했을 때만 발동. "하다 만 옷장" 상태로 세션이 끝나지 않게.
2. **진행바를 절대 0%에서 시작하지 않는다** — 퀴즈 답변을 등록 진행분으로 선환산(부여된 진행 19%→34%).
3. **후반부엔 잔여량 프레임으로 전환** — "3벌 등록했어요"(초반) → "2벌만 더 넣으면 첫 3코디가 열려요"(후반). 목표 구배로 막판 가속.

## 4. 습관 루프 설계 (Hooked 모델)

```
        ┌──────────── 아침 (소비) ────────────┐
        │  트리거: 위젯/알람 "오늘 31도, 3코디"  │
        │  행동:   카드 뒤집기 → 코디 1개 탭     │
        │  보상:   "오늘 뭐 입을지" 결정 면제     │
        │         (가변보상: P=0.5 리빌 연출)     │
        └───────────────┬────────────────────┘
                        │
        ┌──────────── 저녁 (투자) ────────────┐
        │  트리거: 잠금화면 위젯 "반납 모드"     │
        │  행동:   "잘 입었어?" 1탭 + 안 넣은     │
        │         옷 1장 촬영                    │
        │  보상:   착용 도장 + "내일 이 옷 코디"  │
        │  투자:   ▶ 옷 +1, 착용 로그, 체감 피드백 │
        │         = 다음 아침 트리거를 장전       │
        └───────────────┬────────────────────┘
                        ▼  (다음날 아침으로)
```

- **투자가 곧 리텐션 자산:** 등록된 옷·착용 로그·체감 피드백이 쌓일수록 코디가 정확해지고 떠나는 비용이 커진다(Hooked 투자 단계). 등록 노동은 **비용이 아니라 락인 자산**이다.
- **밤이 비어 있는 트리거 슬롯:** 웨디 리뷰가 "자기 전 사용"을 실증. 아침(소비)뿐 아니라 밤(투자)에 두 번째 접점.
- **스트릭은 "등록"이 아니라 "매일 아침 열기"에 건다:** Duolingo 공식 — 면제권 2개 선지급, 7일차 과한 축하, **끊긴 스트릭 화면은 절대 전면 노출 금지**(복구 제안으로만). 비 안 오는 주말은 "날씨 면제일" 자동 부여.
- **시간 지평은 "달 단위":** 습관 자동화 중앙값 66일 → D1 하나로 끝내지 말고 **여름 9주 커리큘럼**(1~2주 외적 보상 → 3~6주 가변 보상 → 7주+ 보상 빼며 "아침=rainism" 맥락 단서만 남기는 페이드아웃).

## 7. 지표 (Metrics)

### 북극성 지표
> **D1 트리거 리텐션** = 온보딩한 유저가 **다음날 아침 앱을 열고 코디를 실제로 탭한 비율.** 다운로드·가입은 허영 지표.

### 활성화 공식 (초기 데이터로 역산·확정할 가설)
> **"48시간 내 상의 4 + 하의 3 등록 & 다음날 아침 코디 1탭."**
> (Facebook "10일 내 친구 7명", Slack "2,000 메시지"처럼 숫자+기한으로 조작 가능한 형태)

### 보조 지표 & 벤치마크
| 지표 | 목표 | 근거 |
|---|---|---|
| 첫 세션 → 첫 코디 도달 시간 | **15분 미만** | 상위 10% SaaS 온보딩 |
| 온보딩(첫 3코디까지) 완료율 | 청킹+진행바+축하로 **완료율 배증** 지향 | 체크리스트 평균 19.2%, 3단계 72% vs 7단계 16% |
| 옷 1벌 등록 소요 | **벌당 ≤30초**(개시식 기준 3~5분/12벌) | Indyx 벌당 2분 · DRESSED 15~20초 |

### 유닛 이코노믹스 감시선
- **태깅:** Gemini Flash $0.003/장, Flash-Lite $0.0006 — 저가 모델로 충분(무료 유저 200벌도 감당). human-in-the-loop 수정 데이터는 파인튜닝 자산(소재 43%→63%).
- **배경제거:** 온디바이스 기본(0원), remove.bg는 fallback($0.11~0.23/장, 발동률을 지표로 관리), 스케일 시 서버 SAM 셀프호스트로 fallback 대체.
