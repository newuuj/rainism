## 큰 그림 — 임계경로

```
Track B (콘텐츠) ─── B0 스파이크용 샘플 100~200장 ──┐
                                                     ↓
Track A (앱)     ─── Phase 0 (스파이크·정책) ────────┴──► Phase 1 (엔진 뺀 앱 전체)
                                                              ↓
Track B ─── B1 매트릭스 → B2 소싱 → B3 시드 50~100장 ────────►Phase 2 (추천엔진) → 3 하드닝 → 4 검증출시
                                    B4 목표규모(~700) ──────────────────────────────────┘
```

**v1과 달라진 핵심:** 스파이크①은 **사진 없이는 시작 못 한다.** 그래서 **B0(샘플 100~200장)이 모든 것의 첫 단추**다. 여기가 늦으면 전부 늦는다.

**여전한 원칙:** 스파이크가 도는 동안 손 놓지 않는다. 추천 엔진을 뺀 앱 전체(Phase 1)는 스파이크 결과와 **무관하게** 먼저 완성한다.

## Phase 0 — 확정 게이트

### ⭐ S0-1. 스파이크① — **어느 표현 방식이 '무드'를 제일 잘 잡나** (가장 중요)

> **이 항목은 2026-07-13에 한 번 뒤집혔다가 되돌아왔다.**
> 프로토타입이 태그만으로 그럴듯해 보여서 *"임베딩 안 써도 되는 거 아니냐"* 는 안이 나왔으나 — **틀렸다.**
> **30장이라서 그럴듯했던 것**이고, 계산해보니 700장에서 태그는 무너진다(아래). `CLAUDE.md`의 확정(**이미지 임베딩 + 벡터 유사도**)이 맞다.

**왜 태그로는 안 되나 — 숫자로**

태그 점수는 `무드(4) × 색(4) × TPO(4)` 조합이라 **점수 종류가 애초에 몇 개 없다.** 라이브러리를 키워도 점수 칸이 안 늘어난다.

| 라이브러리 | 하드필터 통과 | **서로 다른 점수** | **1등 동점** |
|---|---|---|---|
| 30장 (프로토타입) | 20장 | 9개 | **1장** ✅ |
| **700장 (실서비스)** | 460장 | **9개 — 안 늘어남** | **23장** 🔴 |

**700장이면 1등만 23장이 동점**이고, 그 중 3장을 고를 근거가 없다. 프로토타입은 `(id % 7)`로 타이브레이크한다 — **사진 번호순 = 사실상 랜덤.**
→ 경쟁 앱 불만 1위(*"AI 추천이 랜덤 같다"*)를 **우리가 그대로 재현**하게 된다.

**그리고 참고 사진(FR-3/4)이 태그로는 작동하지 않는다.** 유저가 올린 사진을 4가지 무드 중 하나로 우겨넣는 순간 사진의 정보가 다 날아간다. **"사진 1장이면 첫 추천"이 이 제품의 최대 이점**인데(옷 등록 마찰 회피), 그게 임베딩에 걸려 있다.

**비교 대상**

| 후보 | 내용 | 역할 |
|---|---|---|
| 임베딩 모델 ① / ② / … | 이미지 임베딩 → 코사인 유사도 | **본선.** 이 중에서 승자를 고른다 |
| 태그 방식 | 프로토타입 방식 | **바닥선(baseline).** 이기려는 게 아니라, **"임베딩이 최소 이건 넘어야 한다"는 기준선.** 임베딩이 태그보다 못하면 → 모델을 잘못 고른 것이니 다른 모델을 본다 |

**방법:** 같은 사진(B0의 100~200장) + 무드 라벨로 **사람이 top-3 관련성 평가.**

🔴 **판정:** 태그 바닥선을 **넘는** 임베딩 모델 중 1개 확정. 아무것도 못 넘으면 → **모델을 더 찾는다.** (태그로 후퇴하지 않는다 — 700장에서 무너지는 게 계산으로 나왔으므로)

**산출:** 표현 방식 1개 확정 + 취향 프로필 산출법 확정 (🔬 PRD 부록B #1,2)

## Phase 2 — 추천 엔진 + 라이브러리

> 착수 조건: Phase 0 게이트 통과(**표현 방식 확정**) **AND** Track B 시드 50~100장 적재.

### 2A. 라이브러리 적재 파이프라인 (오프라인 배치 · AP-2)

**⬅ v1은 "비전 LLM 태깅" 한 덩어리였다. v2는 태그를 등급으로 나눈다.**

| 등급 | 태그 | 틀리면 | 검수 |
|---|---|---|---|
| 🔴 **안전 태그** | **`rain_ok` · `온도밴드`** | **유저가 젖고 미끄러진다.** 하드필터의 입력이므로 **곧바로 사고** | **사람이 100% 검수** (700장 = 하루) |
| 🟡 일반 태그 | 무드 · 색 · 격식 · 아이템 | "안 예쁨" — 유저가 스스로 거른다 | LLM 출력 그대로 + 샘플 검수 |

> **왜 이렇게 나누나:** 원칙 2 그대로다 — **취향은 틀려도 되고 날씨는 틀리면 안 된다.**
> 그리고 이건 실전에서 확인된 위험이다. 프로토타입에서 폴백이 강수를 완화하는 버그가 **실제로** 났고(2026-07-13 수정), 장마날에 비 부적합 코디를 추천했다. **코드에서 낸 그 사고를, 태그가 틀리면 데이터에서 낸다. 그리고 데이터 버그는 코드 버그보다 안 보인다.**

- 시드 사진 → **라이선스 출처 기록(필수, DR-2)** → 태깅(위 등급대로) → **표현(임베딩) 산출**(스파이크① 승자 모델) → 저장
- 이미지 다중 해상도/썸네일(NFR-5)

🔴 게이트: 시드가 커버리지 매트릭스 최소 셀을 채운다 · 모든 사진에 **라이선스 출처 + 태그** · **안전 태그는 사람 검수 완료**.

### 2B. 추천 경로 (서버 · AP-1)
- 질의 결정(참고사진 있으면 그것, 없으면 취향 프로필 — **어느 쪽 썼는지 기록**)
- **①하드필터 → ②유사도 랭킹 → ③MMR 3장 → ④결정론 이유 문장** (순서 고정, PRD §7)
- **안전빵 1장 보장** · **최근 입은 옷 제외** · **리롤 없음** *(2026-08-17 — 탈출구가 없어져 이 3장의 품질이 곧 제품이다)*
- **폴백 완화 순서(원칙 2, 고정):** **취향 → 체감온도(±1→±2) → 🚫 강수는 절대 완화 불가**
  → 그래도 3장이 안 되면 **2장으로 정직하게 내보낸다.** 사과하지 않는다.
- **이유 문장: 날씨 사실 + 옷 묘사.** 🚫 *"시크 좋아하시죠"* 같은 **취향 단언 금지**(원칙 4)

🔴 게이트: 3장이 뜬다 · 같은 입력=같은 이유(FR-13) · **비 오는 날 비 부적합 사진이 단 한 장도 안 나온다**(자동 테스트) · 3장이 서로 다르다 · 후보 0건에서도 안 깨진다.

### 2C. 결과 화면 완성
- 코디 카드 — **결정하면 「옷장에서 꺼낼 것」 체크리스트로 변신**(08 막힘⑤: 옷장 앞에선 사진이 아니라 아이템 목록이 주인공)
- 취향 프로필 / 참고사진 → 질의 연결
- 로딩 = **스켈레톤**(스피너 금지)

- [ ] 코어 루프가 실제 데이터로 끝까지 돈다
- [ ] 매칭이 "오, 내 취향이네" 수준인지 **내부 눈검사 통과** — **여기서 약하면 화면을 예쁘게 만들지 말고 되돌아간다**(제품의 상한)

## 리스크

- 🔴 **~~북극성이 D1인데 돌아오게 할 장치가 「홈화면 추가」 하나뿐~~ → 2026-08-16에 아침 푸시를 Phase 1로 올려 닫았다.** 대신 **리스크가 옮겨갔다: 이제 제품의 목숨이 「알림 도달」에 달렸다.** 아이폰 웹푸시는 **홈화면에 추가된 PWA + iOS 16.4 이상**에서만 오므로, 홈화면 추가를 안 한 유저에겐 **알림이 아예 안 간다.** → **도달률을 처음부터 계측**해야 한다. 안 그러면 북극성이 안 나왔을 때 **제품이 나쁜 건지 알림이 안 간 건지 구분이 안 된다.** (PRD FR-21b · 08 §5-③)
- 🔴 **오알림이 제품을 죽인다.** 비 온다고 알렸는데 안 오면 유저가 알림을 끄고, 그러면 북극성을 잴 수단 자체가 사라진다. **오알림률을 지표에 넣었다.** 🔬 **발송 임계값(강수확률 몇 % 이상)은 미결정 — 유저가 정한다**(PRD 부록 B #13).
- **매칭 품질이 제품의 상한.** Phase 2 눈검사에서 안 나오면 화면을 예쁘게 만들지 말고 되돌아간다.
- **라이브러리가 진짜 초기 투자처**(~350만원). 서버비(월 13만원)가 아니다.
- **안전 태그(rain_ok·온도밴드) 오류 = 유저가 젖음.** 사람 검수를 건너뛰지 말 것.
- 🚫 **되살리기 금지:** 배경제거 · 옷 조각 태깅 · 조합 엔진 · 요청마다 LLM 이유생성 · 스크래핑 · **노출 라이브러리에 AI 생성 이미지** · 소셜/커머스.
