## A. 처음 시작 (온보딩)

> **시작 → 사진 12장 중 최대 3장 고르기 → 내 옷 고르기 → 동네 → 오늘의 3코디** *(2026-08-17 기준. 성별·나이·색·TPO·참고사진은 모두 폐기)*

| 관련 화면·기능 | |
|---|---|
| 화면 | 시작 · **사진 고르기** · 내 옷 · 동네 |
| 기능 | `pickGender` `pickAge` `acceptConsent` `pickQuiz`×3 `onPhoto` `afterPhoto` `back` |

### ✅ 정상 동작 기준
- [ ] **탭 5~6번**으로 첫 코디까지 도달한다 (**90초 이내**)
- [ ] 취향은 **사진 12장 중 최대 3장을 고른다** (텍스트 아님 — 원칙 4)
- [ ] 여성/20~30대가 아니면 **정직하게 안내하고 돌려보낸다** (거짓 기대 금지)
- [ ] 동의 화면이 **사진·위치를 받기 전에** 나온다 (PIPA)
- [ ] 모든 온보딩 화면에 **← 뒤로**가 있고, 돌아가서 답을 **바꿀 수 있다**
- [ ] 온보딩 질문이 **3개를 넘지 않는다** (원칙 3)

## B. 아침에 오늘 옷 정하기 ★★★ — **이 흐름이 곧 제품이다**

> **앱 열기 → (어제 입었나 답하기) → 날씨 확인 → 코디 3장 훑기 → "오늘 이거 입을래" → 옷장에서 꺼낼 것 확인**

| 관련 화면·기능 | |
|---|---|
| 화면 | **오늘** (하나뿐. 상세 화면 없음) |
| 기능 | `renderResult` `drawSkeleton` `toggleSave` `answerWorn` |

### ✅ 정상 동작 기준
- [ ] 앱을 열면 **0탭으로** 코디 3장이 보인다 (온보딩 다시 안 함)
- [ ] 로딩 중엔 **스켈레톤** (스피너 금지 · 레이아웃이 안 튐)
- [ ] **p95 2.5초 안에** 3장이 뜬다 (NFR-1)
- [ ] 3장 **위에** 날씨 배지가 있다 (근거가 먼저 — 원칙 2)
- [ ] 카드마다 **한 줄 이유**가 있고, **취향을 단언하지 않는다**
      (✅ *"비에도 부담 없는 소재예요"* / ❌ *"시크 좋아하시죠"*)
- [ ] 3장 중 **최소 1장은 "무난해요"** (안전빵 — 신뢰 절벽 방어)
- [ ] **"오늘 이거 입을래" 탭 1번**으로 결정이 끝난다
- [ ] 결정하면 카드가 **「옷장에서 꺼낼 것」 체크리스트**로 바뀐다
- [ ] 결정하면 나머지 2장이 **흐려진다** (결정 끝났다는 신호)
- [ ] **필터·정렬·더보기·상세화면이 없다** (원칙 1)
- [ ] 🔴 **비 오는 날 비에 부적합한 코디가 단 한 장도 안 나온다** ← **가장 중요**

> **목표: 앱을 열어서 닫기까지 탭 2번, 30초.** 넘으면 서연은 어제 그 옷을 입는다.

### ✅ 정상 동작 기준
- [ ] 밤에 열면 **자동으로** 바뀐다 (유저가 스위치를 안 누른다)
- [ ] 제목 = **"내일 아침, 입을 만한 3가지"** · 배지 = **"내일 아침 · ☂ 비 · 체감 23°"**

| 관련 화면·기능 | |
|---|---|
| 화면 | 오늘 |
| 기능 | `reroll` `onResultPhoto` `removeRefPhoto` |

### ✅ 정상 동작 기준

- [ ] 새 3장은 **방금 본 3장과 겹치지 않는다**
- [ ] 다 쓰면 버튼이 잠기고 **"오늘은 여기까지예요"**

- [ ] 🔴 **어떤 경우에도 날씨 하드필터는 그대로다** (비 오는 날 비 부적합 코디 절대 금지)

## E. 어제 입었는지 알려주기 ★★ — **품질을 재는 유일한 눈금**

> **기록 탭 → "아직 안 알려준 날이 N일 있어요" → [입었어요] / [아니요]** *(2026-08-17: 오늘 탭 배너는 뺐다 — 코디 3장을 밀어냈다)*

| 관련 화면·기능 | |
|---|---|
| 화면 | 오늘 (상단 배너) · 기록 (밀린 것 한 번에) |
| 기능 | `renderYdayAsk` `answerWorn` `pendingWornKey` `recentlyWorn` `toggleWorn` |

### ✅ 정상 동작 기준
- [ ] **아직 안 물어본 가장 최근 기록**을 묻는다 (어제만 보면 안 됨 — 주말 건너뛰면 샌다)
      → 금요일 저장 + 월요일 접속 = *"7월 10일에 이거 입었어요?"*
- [ ] **탭 1번** · **무시 가능**(✕) · **화면을 막지 않는다** (FR-20: 낮은 마찰)
- [ ] **[입었어요]** 누르면 → **그 옷이 오늘 3장에서 빠진다** ← 물어본 값을 유저에게 돌려주는 부분
- [ ] 캘린더 셀이 **✓ 표시**로 바뀐다
- [ ] 기록 탭에서 **밀린 것들을 한 번에** 정리할 수 있다

> **왜 재나:** 「입을래」는 눌렀는데 「입었어요」가 안 온 코디 = **예쁘지만 실제론 못 입은 옷.**
> 그게 리스크 #3("내 옷이 아님" 갭)이 새는 정확한 지점이고, **이걸 안 재면 제품의 상한을 모른다.**

## F. 기록 보기

> **기록 탭 → 캘린더 → 날짜 탭 → 그날 코디 + 그날 날씨 → (입었는지 표시)**

| 관련 화면·기능 | |
|---|---|
| 화면 | 기록 (캘린더 · 날짜 상세 모달) |
| 기능 | `renderSaved` `clickDay` `selectDay` `openDayModal` `moveMonth` `toggleWorn` |

### ✅ 정상 동작 기준
- [ ] 셀에 **그날 코디 사진 + 그날 날씨 이모지**가 같이 보인다
- [ ] **「입기로만 함」(점선)과 「실제로 입음」(✓)이 눈으로 구분된다**
- [ ] **빈 상태가 나무라지 않는다** → *"아직 기록이 없어요"* + **[오늘 코디 보러 가기]** (코어로 돌려보냄)
- [ ] 이전 달로 갈 수 있고, **미래 달은 막혀 있다**
- [ ] 🔴 **어디에도 공유 버튼이 없다** (원칙 6 — 나만보기)
- [ ] 🔴 **연속기록·뱃지·통계가 없다** (원칙 5 — 도파민이 아니라 안도)

## H. 아침 알림 켜기

> **오늘 화면 하단 ⏰ 카드 → 시각 선택(07:00) → [알림 받을래요] → 권한 허용 → "내일 아침 여기서 봐요" (홈화면 추가 안내 + 잠금화면 위젯 미리보기)**

| 관련 화면·기능 | |
|---|---|
| 화면 | 오늘 (⏰ 카드) · **설치 안내** |
| 기능 | `renderWake` `enableWake` `scheduleWake` `fireNotify` `testNotify` `fillInstall` |

### ✅ 정상 동작 기준
- [ ] **시각을 유저가 정한다** (07:00 기본, 직접 바꿀 수 있음)
- [ ] 알림에 **오늘 날씨 + 코디 1장**이 들어간다
- [ ] **[알림 미리보기]**로 지금 바로 확인할 수 있다
- [ ] 위젯 미리보기에 **"실물 아님 (네이티브 앱 단계)"**라고 정직하게 쓰여 있다
- [ ] 🔴 **알림을 거부해도 홈화면 추가 안내는 봐야 한다** ← **현재 미충족.** 알림 허용해야만 그 화면에 감

> ✅ **2026-08-16 — 아침 알림이 코어가 됐다** (PRD **FR-21**). 이전엔 *"네이티브 단계 → 스코프 아웃"* 이었고, 이 화면은 그때의 맛보기였다. 이제 **정식 요구사항**이다.
>
> 🔴 **남은 결함 — 순서가 거꾸로다.** 아이폰에서 웹푸시는 **홈화면에 추가해야만** 도착한다. 그런데 지금은 **알림을 허용해야** 홈화면 추가 안내로 넘어간다 → **거부하면 둘 다 못 준다.**
> **① 홈화면 추가 → ② 알림 허용** 순서로 뒤집어야 한다 (FR-21b). *프로토타입 미반영.*

| 없다 | 왜 |
|---|---|
