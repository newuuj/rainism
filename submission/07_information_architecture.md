## 0. 이 문서를 지배하는 한 가지

**북극성 = 알림 도달일 결정률** — *아침 알림을 보낸 날 중, 코디를 하나 정한 날의 비율.* (01 §10 · *2026-08-16 교체 — 이전엔 "D1 아침 트리거 리텐션"*)

정보구조의 최상위는 **기능 목록이 아니라 이 문장**이다. 그래서 위계의 판정 기준은 항상 하나다:

> ### **"이게 내일 아침에 다시 열게 만드는가, 아니면 오늘 아침을 늦추는가?"**

늦추는 것은 전부 아래로 내리거나 없앤다.

## 1. 사용자는 무엇으로 묶어서 생각하는가

**유저는 기능으로 묶지 않는다. 「질문이 생기는 순간」으로 묶는다.** 서연의 머릿속엔 '추천 엔진'도 '캘린더 모듈'도 없고, **아침에 순서대로 떠오르는 질문 네 개**가 있을 뿐이다.

| 서연의 실제 질문 | 그룹 | 앱이 내놓는 답 | 언제 |
|---|---|---|---|
| **"오늘 뭐 입지?"** | **오늘** | 코디 3장 + 탭 한 번 | **매일 아침. 이게 전부다** |
| **"밖이 어떤데? 진짜 비 와?"** | **날씨** | 체감온도·강수 | 3장이 안 믿길 때만 |
| **"나 요즘 뭐 입었더라?"** | **기록** | 날짜별 코디 + 그날 날씨 | 가끔, 저녁에 |
| **"얘가 날 뭘로 아는 건데?"** | **내 취향** | 무드·색·TPO | 거의 안 감 |

### 여기서 나오는 판정 3개

**① 하단 2탭(오늘·기록)은 유저 멘탈모델과 정확히 일치한다.** *(2026-08-17 — 날씨 탭을 오늘 탭 안 카드로 합쳤다. 아래 ② 참고)* 4번째 그룹(내 취향)은 **탭이 아니다.** 설정 안으로 숨긴다 — 눈에 띄면 *"내 취향을 다듬어야 하나?"* 하는 **노동이 생기고**, 그건 원칙 3(보상이 노동보다 먼저) 위반이다.

**② 날씨는 목적지가 아니라 「영수증」이다.** 멘탈모델 M3 — *"날씨앱은 숫자를 준다, 결정은 내가 한다."* 유저는 우리가 결정을 대신 해줘도 **확인 욕구는 남는다.** 날씨 숫자의 진짜 목적은 정보 제공이 아니라 **"앱이 진짜 오늘 날씨를 보고 골랐구나"를 확인시켜 3장을 믿게 하는 것**이다.

> 🔄 **2026-08-17 — 날씨를 독립 탭에서 오늘 탭 안 카드로 옮겼다.**
> **뒤집은 결정:** 2026-07-13에 *"날씨 탭은 날씨만 보여주고 끝낸다"* 고 정했었다(코디 카드를 날씨 탭에 붙이자는 안을 기각).
> **왜 뒤집었나:** 영수증은 **청구서와 같은 종이에 있어야** 한다. 3장을 보다가 *"진짜 비 와?"* 싶을 때 탭을 옮기면, 돌아왔을 때 **결정의 흐름이 이미 끊겨 있다.** 한 탭 거리라도 거리는 거리다.
> **방향이 반대라는 점에 주의:** 기각된 옛 안은 *코디를 날씨 탭에* 넣자는 것이었고, 이번은 *날씨를 오늘 탭에* 넣은 것이다. 코어 탭은 여전히 **오늘** 하나다.
> **대신 지키는 것:** 날씨 카드는 **작게.** 커져서 코디 첫 장이 화면 밖으로 밀리면 원칙(결정 대행)이 깨진다 — 그러면 이 통합은 실패다.
※ 남는 것: 날씨 숫자와 코디는 **같은 화면에서 만나지 않는다.** 그 연결은 **오늘 탭의 날씨 배지 + 카드마다의 한 줄 이유**가 이미 하고 있다고 본다. 검증에서 *"왜 이걸 골랐는지 모르겠다"* 는 신호가 나오면 그때 다시 꺼낸다.

**③ 「저장함」을 따로 만들지 않는다.** 저장 목록과 기록 캘린더를 둘 다 두면 유저 머릿속에서 *"찜한 것"* 과 *"입은 것"* 이 갈라진다. **캘린더가 곧 목록이다.** (프로토타입에 `savedgrid`가 남아 있는데, 캘린더와 중복이다.)

## 2. 위계 — 성공 정의가 최상위

```
[북극성]  내일 아침에도 열고, 코디를 탭한다
    │
    └── L0 · 오늘의 답  ★코어★
        │   앱을 열면 0탭으로 여기. 코디 3장 + 「오늘 이거 입을래」
        │   → 이 화면이 곧 제품이다. 나머지는 전부 이 화면의 부속이다.
        │
        ├── L1 · 답의 근거          "왜 이 3장인데?"
        │     • 날씨 배지(체감온도·강수) — 항상 3장 위에 보인다
        │     • 한 줄 이유 — 카드마다
        │     • 안 믿기면 → 바로 위 [날씨 카드] (같은 화면. 2026-08-17 탭 통합)
        │
        ├── L2 · 답이 틀렸을 때     "이건 좀 아닌데"
        │     • 3장을 못 채운 날 → 정직하게 2장 + 이유 (원칙 2)
        │
        └── L3 · 다시 오게 하는 것   "어제 뭐 입었지?"
              • [기록 탭] — 날짜별 코디 + 그날 날씨 (비공개)
              │
              └── L4 · 답을 만드는 재료
                    • 내 취향 (설정 안. 거의 안 봄)

[관문]  온보딩 — 위계에 없다. 1회성 통과 의례이고, 2회차부터는 존재하지 않는다.
```

### 흔한 IA 실수 두 개를 여기서 막는다

- **온보딩을 IA 최상위에 놓지 않는다.** 온보딩은 **첫 세션에만 존재**한다. 정보구조는 **2회차 이후를 기준으로** 짜야 하는데, 북극성이 **다시 온 날**을 재기 때문이다. 첫날 화면이 아무리 예뻐도 다음에 안 열면 진 것이다.
- **코디 상세 화면을 만들지 않는다.** 상세로 들어가려면 탭이 하나 더 필요하고, 그건 **결정을 한 단계 늦추는 것**이다. 이유·태그·구성 아이템은 **카드에 다 보인다.** (§5 참조)

## 3. 라벨 — 사용자가 쓰는 말로, 같은 행동은 같은 이름으로

### 3.1 지금 프로토타입에서 실제로 깨져 있는 것 🔴

같은 행동 **하나**에 두 개의 언어가 섞여 있다.

| 위치 | 현재 문구 | 어느 언어인가 |
|---|---|---|
| 버튼(누르기 전) | **"🤍 오늘 이거 입을래"** | ✅ **유저 언어 — 결정** |
| 버튼(누른 후) | **"저장됨"** | ❌ 앱 언어 — 보관 |
| 토스트 | "오늘 코디로 **저장**했어요 ♥" | ❌ 앱 언어 |
| 캘린더 안내 | "**저장**하면, 그 날짜 칸에 담겨요" | ❌ 앱 언어 |

유저는 방금 **"오늘 이거 입을래"** 라고 결정했는데, 앱은 **"저장됐다"** 고 답한다. → 유저 머릿속: *"내가 결정한 건가, 그냥 찜한 건가?"*

**이게 왜 치명적인가:** "저장"은 **핀터레스트의 말**이고, 뜻은 *"나중에 볼게"* 다. 우리 제품은 *"나중에 볼게"* 를 파는 게 아니라 **"오늘 이걸로 끝"** 을 판다. 라벨 하나가 제품을 핀터레스트 쪽으로 끌고 간다. (01 §4 — 핀터레스트와의 차이가 제품의 존재 이유다.)

### 3.2 라벨 사전 (정본)

> **규칙: 같은 행동은 어디서든 같은 이름. 앱 내부 용어는 화면에 절대 안 나온다.**

| 행동/대상 | ✅ 쓸 말 | ❌ 쓰지 말 말 | 왜 |
|---|---|---|---|
| **코디를 오늘의 것으로 정함** | **"오늘 이거 입을래"** → 누른 뒤 **"오늘 입기로 했어요"** | 저장 · 저장됨 · 찜 · 담기 | 이건 **보관이 아니라 결정**이다 |
| **실제로 입었는지 확인** | **"입었어요"** → 누른 뒤 **"입었어요 ✓"** | 착용 확인 · 체크인 | "입을래 → 입었어요"로 **시제만 바뀐다.** 같은 흐름의 같은 언어 |
| **되돌리기** | **"안 입을래"** / **"안 입었어요"** | 취소 · 삭제 · 저장 해제 | 위와 대칭 |
| **3장이 마음에 안 듦** | **(따로 주는 길이 없다)** *(2026-08-17: "다른 거 보여줘" 폐기)* | 다른 분위기로 3개 더 · 새로고침 · 리롤 | 탈출구를 열면 결정 피로가 돌아온다 |
| **취향 질문** | **"내 취향"** (온보딩·설정 동일) | 취향 퀴즈 · 추구미 진단 · 테스트 | '퀴즈/테스트'는 **정답이 있다는 뉘앙스** → 원칙 4와 충돌(정답 없다) |
| **탭 1** | **오늘** | 홈 · 추천 | 유저의 질문이 "오늘 뭐 입지"다 |
| **탭 2** | **날씨** | — | 그대로 좋다 |
| **탭 3** | **기록** (화면 제목 "코디 기록") | My · 마이페이지 · 내 옷장 | "My"는 **뭐가 들었는지 알 수 없는 이름**. "내 옷장"은 **거짓말**(내 옷 아님 → 원칙 5) |

### 3.3 화면에 절대 나오면 안 되는 내부 용어

**안전빵 · 하드필터 · 분위기 유사도 · MMR · 다양성 보장 · 임베딩 · taste_vector · 체감온도 밴드 · 라이브러리 · 콜드스타트**
→ 전부 **우리끼리 쓰는 말**이다. 특히 **"안전빵"** 은 문서 용어이지 라벨이 아니다. (현재 프로토타입엔 `safechip`이 카드에 노출된다 — 유저에게 보여줄 거면 *"무난해요"* 같은 말로 바꾸고, 아니면 뺀다.)

### 3.4 취향을 언어로 단언하지 않는다 (원칙 4 따름 규칙)

- ✅ **"체감 23도, 종일 비 소식이에요"** — 사실. 반박 불가.
- ❌ **"시크한 당신을 위해"** — 단언. *"내가?"* 로 반박당한다.

추천 이유는 **날씨 사실**로만 쓴다.

## 5. 만들지 않는 화면 — 그리고 왜

| 안 만드는 것 | 왜 |
|---|---|
| **코디 상세 화면** | 탭을 하나 더 요구 = **결정 지연.** 이유·태그·아이템은 카드에 다 있다 (원칙 1) |
| **저장함 / 찜 목록** | **캘린더가 곧 목록.** 둘 다 두면 "찜한 것"과 "입은 것"이 갈라진다 (§1-③) |
| **필터 · 정렬 · 태그 탐색** | 결정을 유저에게 되돌려주는 행위 (원칙 1) |
| **무한 스크롤 / 더 보기** | 위와 같음. **3장이 전부다** |
| **피드 · 공유 · 프로필** | 사적 실행 × 공적 판단 (원칙 6) |
| **옷 등록 · 옷장** | 경쟁 앱 1순위 이탈 원인 (원칙 3 · PRD §5 OUT) |
| **날씨 직접 선택 화면** | 프로토타입 `s-weather`는 **데모 전용.** 실서비스에선 기상청에서 자동 (PRD FR-7) |

---

## 6. PRD엔 있는데 화면이 없는 것 🔴 (착수 전 채울 것)

| 빠진 것 | 근거 | 지금 상태 |
|---|---|---|
| **"입었어요" 착용 확인** | FR-20 (✅ 확정) | **프로토타입에 0회 등장.** 저장만 있고 착용 확인이 없다 |
| **개인정보 동의 · 처리방침** | RG-1 (PIPA) | 없음. 사진·위치를 받으려면 **법적으로 필수** |
| **위치 권한 / 동네 수동 선택** | FR-8 | 없음 (데모라 날씨를 직접 고름) |
| **로그인 / 본인 데이터 보호** | FR-16 · §11 | 없음 (localStorage) |

> **"입었어요"가 없으면 캘린더가 반쪽이다.** 「입을래(결정)」와 「입었어요(실행)」의 간극이 곧 **매칭 품질의 진짜 지표**인데(저장은 했지만 안 입었다 = 추천이 예뻤지만 못 입을 옷이었다), 지금은 그걸 못 잰다. **북극성 지표 계측에 직결된다.**

## 7. 요약 — 한 화면에 다 넣으면

```
┌─ 온보딩(1회) ─────────────────────────────┐
│ 시작 → 성별 → 나이 → 취향①사진 ②색 ③TPO   │
└───────────────────────────────────────────┘
                    ↓  (두 번 다시 안 봄)
┌─ 매일 아침 ───────────────────────────────┐
│                                           │
│   [오늘] ★ ← 앱을 여는 유일한 이유        │
│     날씨 배지 → 3장 → "오늘 이거 입을래"  │
│        ↓ (의심되면)                        │
│   [날씨] ← 확인용. 탭바로 언제든 복귀      │
│                                           │
│   [기록] ← 내일 다시 오게 하는 것          │
│     날짜 → 그날 코디 → "입었어요"         │
│                                           │
└───────────────────────────────────────────┘
        설정 ⚙ : 내 취향 · 내 동네 · 계정
```

---

*정보구조의 성패는 화면 수가 아니라 **아침에 몇 번 탭해야 결정이 끝나느냐**로 잰다. 목표 = **1번.***
