## 1. Happy Path

북극성이 **다시 온 날**을 재므로(2026-08-16 = *알림 도달일 결정률*) 성공 경로는 **하나가 아니라 둘**이다. 첫 세션만 성공하고 다음 아침에 안 오면 **진 것**이다.

### 1-A. 첫 세션 — "이 앱이 뭐 하는 앤지 알겠다"

```
설치/진입
   ↓
[시작]  "오늘 뭐 입지, 내가 대신 골라줄게요"          ← 약속을 건다
   ↓ 탭
[성별] → [나이]                                       ← 니치 스크리닝
   ↓ 탭 ×2
[내 취향 사진고르기] 사진 12장 중 최대 3장             ← 말이 아니라 사진 (원칙 4)
[내 취향 ②색]    옷장에 제일 많은 톤
[내 취향 ③TPO]   자주 가는 곳
   ↓ 탭 ×3
   ↓ 사진 올림                                        │
   ↓                                                  ↓
┌──────────────────────────────────────────────────────┐
│  ★ [오늘]  날씨 배지 → 코디 3장 → 한 줄 이유         │  ← 보상. 노동보다 먼저 온다
└──────────────────────────────────────────────────────┘
   ↓ 탭 1번
[오늘 이거 입을래] → 토스트 "오늘 이걸로 정했어요"
   ↓
✅ 첫 세션 완료 —  탭 6~7번, 목표 90초 이내
```

### 1-B. D1 아침 — **진짜 성공은 여기다**

```
아침 8:10, 비. 앱을 연다 (온보딩 없음. 0탭으로 [오늘])
   ↓
   ↓ 탭
[오늘]  ☂ 비 · 체감 23°  →  코디 3장
   ↓ 탭
[오늘 이거 입을래]
   ↓
✅ 완료 —  **탭 2번, 목표 30초.** 앱을 닫고 옷을 입는다
```

> **성공의 정의를 화면으로 옮기면:** *아침에 앱을 열어서 닫기까지 **탭 2번, 30초.*** 이걸 넘으면 서연은 어제 그 옷을 입는다.

## 3. 예외 흐름

> 원칙: **빈손을 보여주지 않는다**(FR-14). 그리고 **못 하는 걸 숨기지 않는다**(원칙 5). 이 둘을 동시에 지키는 방법 = *"뭘 못 했는지 말하고, 그래도 뭔가는 준다."*

| 상황 | 지금 어떻게 되나 | 어떻게 해야 하나 |
|---|---|---|
| **기상청 API 장애** | 캐시로 계속 동작 (FR-9) | 그대로. 단 **"어제 오후 기준"** 처럼 **언제 값인지 밝힌다** |
| **캐시도 없음** (첫 실행 + API 다운) | 🔴 **진짜 빈손.** 날씨를 모르면 하드필터를 못 건다 | **날씨를 물어본다** — *"지금 밖에 비 와요?"* 2택. (프로토타입의 날씨 선택 화면이 **바로 이 폴백**으로 재활용됨) |
| **위치 권한 거부** | ✅ **[동네를 골라주세요]** 화면 (🧪 `geo=deny`) | 그대로. 거부는 실패가 아니라 **다른 입력 경로** |
| **기록 탭 사진 모더레이션 차단** (FR-5) | 🔴 미정 | *"이 사진은 못 써요"* + 기록은 그대로 남긴다. 막다른 길 금지 *(2026-08-17: 참고사진 폐기로 대상이 기록 탭 사진 하나만 남았다)* |
| **사진 용량 초과 / 형식 오류** | 🔴 미정 | 업로드 **전에** 클라이언트에서 압축·변환 (NFR-5). 유저에게 에러를 안 보여주는 게 최선 |
| **하드필터 0장** | 폴백 화면 | 온도 완화 → 그래도 없으면 **2장**. **강수는 절대 완화 안 함** (원칙 2) |
| **저장 중 네트워크 끊김** | 🔴 미정 | **낙관적 UI**(먼저 ♥ 표시) + 실패 시 조용히 재시도. **아침에 에러 팝업을 띄우지 않는다** |
| **로그인 세션 만료** | 🔴 미정 | 추천은 **그대로 보여준다**(읽기는 인증 불필요하게). 저장하려는 순간에만 로그인 요구 |
| **완전 오프라인** | 🔴 미정 | PWA 캐시로 **어제 코디 + 마지막 날씨**를 보여주고 *"오프라인이에요"* 표시 |
| **후보가 3장이 안 됨** | 2장만 보여주고 **이유를 준다** — *"오늘 날씨에 맞는 게 이만큼이라서요"* | 부실이 아니라 **판단**임을 보이기 (M4) |

## 5. 🔴 시뮬레이션 — 서연, 화요일 아침 8:10, 장마

> 규칙: **좋게 봐주지 않는다.** 서연은 앱을 도와주려고 쓰는 사람이 아니다.
> ⚠️ **아래는 2026-07-13에 걸어본 기록이다. 고치기 전 상태로 그대로 둔다** (왜 그렇게 정했는지가 여기 있으니까).
> **지금 프로토타입이 어디까지 왔는지는 [§6](#6-그래서-무엇부터-고치나--그리고-어디까지-고쳤나)에 있다.** 여기서 나온 막힘 중 **②③⑤⑧은 고쳤고, ⑦은 남았다.** (①·⑥은 아직 확인 안 함)

- **화요일 아침 8:10** — 비. 9시 수업. 준비 30분. **옷 결정에 쓸 수 있는 시간 3~5분.**

### 🔴 막힘 ② — **첫 진입은 아침이 아니다**

**이게 가장 큰 구멍이다.** 서연은 **아침 8시에 새 앱을 설치하지 않는다.** 아침엔 그럴 시간이 없다. 첫 온보딩은 거의 항상 **밤이나 한가한 시간**에 일어난다.

그런데 우리 온보딩의 보상은 **"오늘의 3코디"** 다. 밤 11시에 그걸 보여주면 **이미 끝난 날의 코디**다. 서연은 그걸 저장할 이유가 없다.

> **"보상을 노동보다 먼저 준다"(원칙 3)의 보상이, 쓸모없는 보상이 된다.**

**→ 고칠 것:** 진입 시각으로 갈라야 한다.
- **04~11시** → *"오늘 입을 3가지"*
- **그 외** → *"**내일 아침** 입을 3가지"* + 내일 날씨로 하드필터
그리고 밤 온보딩의 끝은 **저장이 아니라 "내일 아침에 다시 열기"** 여야 한다. (지금 프로토타입은 무조건 "오늘". **B8 분기 없음.**)

| 11:20:50 | 3장을 본다 | | ✅ **"오, 예쁘네"** — 여기까진 성공 |
| 11:21:00 | 앱을 닫는다 | | 🔴 **③** **저장 안 함.** 오늘 밤엔 입을 일이 없으니까 |

### 🔴 막힘 ③ — **다음 아침에 돌아올 장치가 하나도 없다** *(2026-08-16 갱신)*

내일 아침 서연이 이 앱을 **기억할 이유가 없다.** 당시 상황은 이랬다:
- 푸시 알림 → ~~MVP 스코프 아웃(네이티브 단계)~~ → **✅ 2026-08-16 코어로 승격 (FR-21)**
- 홈 위젯 → **여전히 스코프 아웃** (네이티브가 있어야 한다)
- 홈화면 추가(PWA) → **안내 화면 없음** 🔴

**즉, 북극성 지표를 재는 장치가 제품에 없었다.** 계측 문제가 아니라 **제품 구멍**이었다.

**→ 고친 것 (2026-08-16):** **아침 알림 1회를 검증 MVP 안으로 들였다**(FR-21). 첫 세션의 마지막 화면은 저장 확인이 아니라 **"내일 아침 여기서 봐요 — 홈화면에 추가"** 다.

**→ 🔴 아직 남은 것:** **순서가 거꾸로다.** 아이폰 웹푸시는 **홈화면에 추가해야만** 도착하는데, 지금은 **알림을 허용해야 홈화면 추가 안내로 넘어간다.** 알림을 거부하면 **둘 다 못 준다.** → **① 홈화면 추가 → ② 알림 허용** 순서로 바꿔야 한다 (FR-21b). *프로토타입 미반영.*

### 🔴 막힘 ⑤ — **"이제 뭘 입지?"** (리스크 #3이 새는 정확한 지점)

서연은 결정을 **끝냈다고 생각했는데**, 옷장을 열자 **흰 퍼프 블라우스가 없다.** 사진 속 옷은 **그녀 옷이 아니다.**

이 순간 앱이 그녀에게 준 것은 딱 하나 — 카드 맨 아래 **12px 회색 텍스트**:
> *화이트 퍼프 블라우스 · 데님 쇼츠 · 레인부츠*

**이 한 줄이 "남의 사진"과 "내 옷장" 사이의 유일한 다리다.** 그런데 지금 카드에서 이게 **가장 작고, 가장 흐리고, 맨 아래에 있다.**

**→ 이건 정보구조의 우선순위 오류다.** 우리는 사진이 주인공이라고 생각했는데, **실행의 순간엔 아이템 텍스트가 주인공**이다. 사진은 *"오 이런 느낌"* 을 주고, **아이템 목록이 실제로 옷장에서 옷을 꺼내게 한다.**

**고칠 것 (셋 중 택1 — 🔬 유저 테스트로 결정):**
1. **아이템 텍스트를 카드에서 승격** — 이유 문장과 같은 크기·색으로. (가장 싸다)
2. **"비슷한 거 찾기" 체크리스트** — *"흰 블라우스 있어요? / 데님 쇼츠? / 레인부츠?"* → 없으면 그 아이템 뺀 코디로 다시 추천.
3. 아무것도 안 함 — **갭을 인정하고 산다** (원칙 5). 대신 **결정률 대비 "입었어요" 비율**로 이 손실을 **잰다.**

> **"입을래"는 눌렀는데 "입었어요"가 안 오는 코디 = 정확히 이 벽에 부딪힌 코디다.** 그래서 「입었어요」가 계측용 버튼이 아니라 **리스크 #3의 유일한 온도계**다.

| 8:10:20~ | 옷장에서 **비슷한 흰 블라우스**를 찾는다 | (앱은 아무것도 안 함) | ⚠️ 여기서 3분이 다시 흐를 수 있다 |
| 8:13 | 대충 비슷하게 입고 나감 | | ⚠️ **절반의 성공** — 결정은 대신 해줬지만 **실행은 혼자 했다** |

### 🔴 나머지 막힘

**⑥ 3장이 다 별로인 날.**
8:10:15에 3장이 다 아니었다면? **아무것도 할 수 없다** *(2026-08-17: 「다른 거 보여줘」 폐기)*.
→ 서연은 앱을 닫고 **어제 그 옷을 입는다.** 이게 감정지도 ⑤(대충 회귀)로의 복귀 = **완전 실패.**
→ 원칙 1(**탈출구 없음**)의 **대가**다. 감수하되, **그 순간 최소한 이유는 준다** — *"오늘 비 오는 날씨에 맞는 게 이만큼이라서요."* 부실이 아니라 **판단**으로 읽히게(M4). 이제 이 대가가 이전보다 크다 — **3장의 품질이 곧 제품이다.**

**⑦ 온보딩에서 되돌아가면 이전 답이 안 보인다.**
뒤로가기는 넣었는데, 돌아온 화면에 **내가 뭘 골랐었는지 표시가 없다.** 다시 처음부터 고민해야 한다.
→ 선택했던 항목에 **선택 표시**를 남긴다. (작은 수정)

**⑧ 주말에 안 열면 "어제 배너"가 영영 안 뜬다.**
금요일에 저장하고 주말을 건너뛰면, 월요일 아침의 "어제"는 **일요일**(기록 없음)이라 배너가 안 뜬다.
→ **"어제"가 아니라 "마지막 미응답 기록"** 을 물어야 한다. *"금요일에 이거 입었어요?"*

### 3번은 왜 4번째 답이 됐나

문서는 *"아이템 텍스트를 카드에서 크게"* 를 1안으로 뒀는데, 만들어놓고 보니 **고르는 순간엔 그게 방해였다.** 읽을 게 많을수록 결정이 느려진다.

**→ 시점으로 갈랐다.**
- **결정 전** = 사진이 주인공. 아이템 목록은 **아예 안 보여준다.**
- **결정 후** = 고른 카드에만 **[옷장에서 꺼낼 것] 체크리스트**가 펼쳐진다.

8:10:18에 필요한 건 사진이고, 8:10:20 **옷장 앞에서** 필요한 건 목록이다. 같은 화면이 시점에 따라 다른 걸 준다.
